## 文档分工原则

| 文档 | 定位 | 什么时候会过期 |
| --- | --- | --- |
| README | **门面**：是什么、怎么跑、有什么能力 | 改功能 / 改命令时 |
| 使用指南 | **上手**：装、跑、排查 | 改启动方式 / 改环境变量时 |
| 架构设计 | **原理**：为什么这么设计 | 改架构 / 改关键取舍时 |
| 接口一览 | **契约**：端点与 SSE 协议 | 改接口时 |
| AGENTS.md | **AI 入口**：命令、硬规则、坑 | 改代码约定 / 踩新坑时 |
| 交接文档 | **状态快照**：现在什么样、接下来做什么 | 每次功能批次结束时 |
| 作品集/参赛/ | **对外材料**：给评委看的 | 改功能或改数字口径时 ⚠️ 最易滞后 |
| CHANGELOG | **历史**：每批改了什么 | 每批结束时 |

> ⚠️ **作品集里凡是写了功能状态与数字的地方，改代码后必须回来核对** ——
> 材料写"计划中"而演示里能用，或材料写 9 题而实际 35 题，都会成为前置审查问题。
> 核对入口是 [02-主张与证据核对表](作品集/参赛/02-主张与证据核对表.md)。
