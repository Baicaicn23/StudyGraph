## 一、这个项目是什么（自包含简介）

**知迹 是一个面向大学生的 AI 学习私教 + 学习管理台**，Web 优先
（Next.js 16 前端 + FastAPI 后端 + SQLite）。核心痛点：**作业散落在各课程系统里，
平时不整理，期末没有题可复习**——所以知识库是"平时的沉淀罐"，期末从库里长出
复习材料（检索 → 出题 → 间隔重复 → 掌握度），再加上日程把"什么时候做"也管起来。

技术上用 **LangGraph** 把一次学习回合做成显式状态图（`route → plan → agent ⇄ tools`），
配齐 Agent 工程模块：意图路由、工具最小权限、人在环（HITL）、护栏、工具可靠性、
上下文压缩、规划、模型路由、成本控制、MCP、评测门禁、回合 trace。

**项目定位**：**全国大学生数字媒体科技作品及创意竞赛（赛道十三：智慧教育与智能软件类）**
参赛作品。一切决策以"可交付、可演示、材料与代码一致"为准。

- git 推送需走代理隧道（代理 `127.0.0.1:8086` 不在时推送失败，先 `nc -z 127.0.0.1 8086` 探测）：
  `GIT_SSH_COMMAND="ssh -o ProxyCommand='/usr/bin/python3 ~/.ssh/gh-connect.py %h %p'" git push`
- 后端 / 前端 dev server 随会话回收。重启：
  `uv run uvicorn zhiji.interfaces.api:app --port 8011`（**改后端代码必须重启，没有 --reload**）
  与 `cd frontend && npm run dev`。
- **UI 真实验证可用 `agent-browser`**（Chromium 已就绪）：
  `export PATH="/Users/momo/.workbuddy/binaries/node/versions/22.22.2-6/bin:$PATH"` →
  `agent-browser open <url>` / `snapshot`（a11y 树带 ref）/ `eval <js>` / `click <sel>`。
  排查"按钮点了没反应"最快：先 curl 验后端，再浏览器验前端；测完还原用户数据。
  ⚠️ **必须用 `http://localhost:3000`，不能用 `http://127.0.0.1:3000`**（2026-10-13 踩坑）：
  Next 16 dev 把 `127.0.0.1` 当**跨源**请求拦截开发资源（终端可见
  `⚠ Blocked cross-origin request to Next.js dev resource /_next/hmr from "127.0.0.1"`），
  HMR 客户端不加载 → 页面**完全不 hydrate** → 所有按钮点了没反应、打字后发送按钮不亮，
  而 HTML/JS chunk 全 200、DOM 也渲染正常，极易误判成业务 bug。**判定手法**：往输入框
  打字后看「发送」按钮的 `disabled` 是否解除（它由 React state 驱动）；或看真实点击后
  `aria-expanded` 是否变化。**`agent-browser eval` 里用 `.click()`/合成事件不触发 React
  处理器**（未 hydrate 之外的第二个陷阱），要验证交互必须用 `agent-browser click <sel>`。
  只有 `<a href>` 能"点得动"——那是浏览器原生跳转，不能用来证明页面活着。

### 前端坑（本轮踩过，别再踩）

- **手写 SSE 解析别硬编码偏移**：`"event: "` 长 7，曾写 `slice(6)` 导致 `done` 帧匹配不上、
  出题结果恒为空。用 `slice("event: ".length).trim()`。
- **新增 SSE 事件类型必须同步 `parseEvent` 的分支**：`step` 事件曾只加了类型声明、漏了
  `case "step"`，结果过程流被解析器静默丢弃（用户反馈"说完不知道智能体干了什么"）。
  改协议后先 grep `parseEvent` 确认每个事件都有分支。
- **SSR 组件里"客户端才知道"的状态必须走 `useSyncExternalStore`**（服务端快照恒 false），
  不能用 lazy `useState` 直读 `window`——否则 hydration mismatch（曾让 /practice 红屏）。
  参考 `components/useMediaQuery.ts`（含 `useMounted()`）。
- eslint `react-hooks/set-state-in-effect`：effect 体内同步 setState 会报错。对策：数据加载走
  `.then()` 链；派生状态（如 `view ?? selectedMonth`）代替 effect 同步；定时器里才 setState。
- **flex 链上的 `truncate` 不生效 = 某层缺 `min-w-0`**（整条父子链都要能收缩）。
- 带提前 return 的组件，**hooks 必须放在 return 之前**（如 MessageRow）。
- 跨页动作传递若依赖"导航后重新挂载"，目标页已是当前页时会失效——用
  `zhiji-chat-action` + `zhiji:chat-action` 双通道（sessionStorage + window 事件）。
- Next.js 16：新增动态路由必须加 Suspense 边界；`cacheComponents` 下渲染期禁 `Math.random()`。
- 自定义 CSS 效果（mask 渐变等）在用户浏览器不可靠——**UI 细节优先用最朴素的 Tailwind 工具类**。
- **Radix Popover 弹层**（＋菜单/选库/空间/模型四处）：Trigger 与 Content 必须同 Root——
  受控状态下平按钮触发时加 `onPointerDown={(e) => e.stopPropagation()}`，否则点外关闭
  与 click 切换双触发闪烁；面板定位用 `Popover.Anchor`（置于原锚位）+ Content
  `side/align/sideOffset`，别再手写 fixed overlay。
- **useCallback 的依赖数组收尾是 `[],` 不是 `]);`**——锚点字符串写错会让删除整段
  handler 的脚本静默失配。

  `KnowledgeStore.search()` 里（`[1.0, expansion_weight, 0.8, 1.0]`）。**加新能力请加
  通道，别改 `_query_terms()`**——它决定原查询 FTS 词，一动就会变评测基线。
- `_STOPWORDS` 只作用于**短词 LIKE 路**（两字词里的虚词会把召回掐死）。别顺手拿去
  过滤 FTS 词：那是老链路的既有行为，且改完必须重跑评测门禁。
- 同义词表（`domain/synonyms.py`）**只收无歧义的等价术语**：多扩会污染精确率，
  所以扩写路按 0.5 降权。加词前先想"这条会误召回什么"。
- 同义/英中匹配用 `_contains()`：英文按**词边界**（否则 `sort` 命中 `consortium`），
  中文按子串；单字符术语一律忽略。
- **`uv run zhiji-eval retrieval` 的基线是判定标准**：改检索后必须跑，Hit@K / MRR
  掉超过 0.05 容差即退出码 1。数据集在 `evals/datasets/retrieval.json`（用例可带
  `note` 说明考点）；`--update` 才重写基线。
- **新增工具必须同步进 `domain/guardrails.py` 的 `_TOOL_LEAK_MARKERS`**：它拦住"正文
  泄漏内部工具名"（教学总纲「技术过程内隐」的执行层兜底）。漏挂会对新工具失去兜底，
  但这条由 `test_tool_leak_markers_cover_registry` 守住，漏了会红。
- **改教学人格提示词后，跑 `tests/test_agent_modules.py`**：它断言总纲各段（三条红线 /
  输出规格 / 技术过程内隐 / 绝对禁止）与分场景骨架**真的拼进了系统提示词**——文案改了
  但断言里的锚点串没跟着改，测试会红（这是有意的：防止"改了文案其实没生效"）。
- `build_system_prompt` 的拼接顺序是**稳定前缀在前、动态内容在后**（缓存友好，别打乱）。
- **工作区文件工具（`write_file` / `read_file` / `list_files`）**：`_workspace_dir()` 必须
  返回 **resolve 过的绝对路径**。`_safe_resolve()` 返回的是绝对路径，两边不一致时
  `path.relative_to(_workspace_dir())` 会在**文件已经写完落盘之后**抛
  `ValueError: ... is not in the subpath of ...` —— 现象极具迷惑性：**盘上有文件、工具却
  报「写入失败」**，模型于是对学生说"写入出了点问题"。生产默认 `data/zhiji.db` →
  `configure_workspace(Path("data/zhiji.db").parent / "workspace")` 是**相对**路径，所以线上必现；
  而 `tests/` 的 fixture 传 `tmp_path`（绝对）**永远测不出来**——改这里必须跑
  `test_relative_workspace_root_matches_production`（专门用相对 root 复现生产装配）。
- `user_id` 是**客户端可传的**（`Field(default="local", max_length=64)`，只限长度）。它会被拼成
  工作区目录名，所以必须过 `_safe_user_segment()` 压成**单层安全目录名**：否则
  `user_id="../../../../tmp/x"` 会让 `mkdir(parents=True)` 在工作区**之外**建目录并写入。
- **`ChatRequest` 的字段声明与读取处必须同时改**（M14.2 最严重的一颗雷）：pydantic 对**未在模型上
  声明的入参一律静默丢弃**，读它才 `AttributeError` → 500。`retrieval_mode` 曾漏声明，于是
  **只要 `knowledge_bases` 非空就 500**——前端「指定知识库」模式从来没成功过，且因为 `auto` 是
  唯一消费点，`graph.py` 里的「智能选库」分支实际从未运行。加接口参数时两处一起动。
- **删除类接口必须做级联（本项目没有外键，全靠手写 SQL）**，已确立的联动都由回归测试守住：
  删误区 → 连带删**派生题 + 作答记录**；删资料 / 删整库 → 连带删**引用其片段的题**；删项目 →
  连带删**记忆 + 会话 + 消息 + 附件 + 检查点线程**；删会话 → 连带删**检查点线程**。
  新增任何"派生物"（题、笔记、摘要…）时先问一句：**它被删了，谁还指着它？**
- **LangGraph 检查点与会话是两套存储**：只删 `chat_sessions` 会留下 `checkpoints` / `writes` 里的
  孤儿线程——**用户以为删掉的对话仍能从中还原正文**（实测曾累积 33 线程 vs 7 会话）。删会话要调
  `request.app.state.graph.checkpointer.adelete_thread(thread_id)`；清理前先用
  `chat.count_sessions_with_thread()` 确认没有别的会话共享该 thread_id（thread_id 是客户端传的、
  缺省 `"web"`，极端情况会共享）。清理失败**不要**让删除接口报错。
- **UNIQUE 约束要在接口层翻译成 4xx**，全项目三处：`projects(user_id, name)`、
  `practice_questions(user_id, source_feedback_id)`（部分唯一索引）、`memories(user_id, project_id, content)`。
  `sqlite3.IntegrityError` 不上抛成 409 就是 500——`POST /api/projects` 早就 409，`PUT` 重命名漏了，
  撞名时直接 500（**只在跨行撞名时触发**，改回自己原名不算冲突）。
- **同一资源的归属校验状态码要一致**：会话的 GET messages / PUT / DELETE 对非归属或不存在统一 404，
  别再出现"200 + 空列表"——调用方分不清"没消息"和"不是你的会话"。
- **`documents.kind` 是状态机，不是类型**：`file`（原样秒传，未解析）→ 解析后升级为
  `file_text`（**原件仍然保留在盘上**）。所以**读原件的查询必须同时接受 `file` 和 `file_text`**
  （`get_document_file` 已修）：只认 `file` 会让「解析入库」之后阅读页的「原件」tab 和
  「下载原文」全部 404 —— 症状是**解析前正常、解析后反而坏**，从界面上很难联想到原因。
  新增 / 修改按 `kind` 过滤的查询时，先想清楚"这两个状态该不该都算"。
- **演示素材是代码资产，不是手工数据**：`assets/demo_materials/`（受版本控制）+ `scripts/build_demo_materials.py`
  （生成用，用 `uv run --with` 临时装依赖）。**不要手工往库里塞演示数据**——那样 `zhiji-demo --reset`
  一跑就没了。素材正文**必须是自编内容**，换成教材扫描件会破坏「来源与授权清单」的版权口径。

## 八、设计决策记录（防翻案，含理由）

| 决策 | 理由 |
| --- | --- |
| 对话不允许跨项目移动 | 记忆按 project_id 隔离，移动会话=上下文与项目错配的脏数据 |
| 删除项目=连对话一起删 | 项目是"一段工作"的容器；用户拍板"全部删掉不留" |
| 错题本/练习/掌握度/日程是全局的 | 刻意不按项目隔离（错题应跨项目累积） |
| 无 project_id 的请求兜底「未归类」 | 否则记忆落 `project_id=''` 黑洞桶，表现为"记住又忘了"；但新对话必须显式选课程，不做默认分配 |
| 误区带「错误类型」与学科正交 | 学科答"哪个知识点"，类型答"为什么错"；智能分类按类型聚合即可给出可行的回炉方向 |
| 错题本与练习合并为一页两 tab | 两者本是一套闭环（沉淀 → 针对性练习）；一级入口只留「错题练习」，避免并列重复 |
| 会话步骤(step)随消息落库 | 历史回放要能看到当时的思考/工具过程 |
| 中断前后的文字与步骤合并成同一条消息 | 否则历史里只剩"确认之后"的半截过程；续写时用 `last_assistant_message` + `update_message` 并回原消息 |
| 文件工具写进沙箱工作区、不做 HITL | 写不出去沙箱（路径穿越全拒绝），风险可控；每次写文件都弹确认会毁掉交互节奏 |
| 搜索流水线：DeepSeek 原生搜索优先 → 多后端回落 → 概念覆盖过滤 | 主模型是 DeepSeek 时自动走其服务端 `web_search_20250305`（搜索+抓全文+基于全文整理答案，一次调用覆盖多查询角度，中文质量最好的路径，复用同一把 Key）；实测必应中国对部分中文查询整页跑偏（"四级作文模板"返回报名官网）——零配置时必应+DDG **双路并发合并**互相兜底；配 Key 可选博查（中文付费最优）/Tavily；结果按**概念覆盖**过滤：查询剥指令词、按空格拆概念段，须盖住某查询全部段才算全相关（只沾"四级"的报名页直接过滤），无全盖保留覆盖率 ≥50% |
| 联网搜索 DDG 兜底 + 博查/Tavily 可选 | 零配置可演示（必应+DDG 双引擎）；本网络下 DDG 需代理，配 `ZHIJI_BOCHA_API_KEY`/`ZHIJI_TAVILY_API_KEY` 走 API 更稳；失败诚实降级 |
| 思考默认固定最大档，不做强度选择 UI | 实测 DeepSeek V4.1-Flash 对 reasoning_effort 分档无响应（low/max 思考 token 持平），有效控制轴是 thinking 开关——做"关"才有意义而 GLM-5.3 又不支持禁思考；用户拍板撤下选择 UI，恒 thinking=max |
| 弹层用 Radix Popover（＋菜单/选库/空间/模型） | 无障碍基座（ESC/点外关闭/焦点管理）手写难做全；视觉仍是自己的 Tailwind 类；触发按钮 onPointerDown stopPropagation 防点外关闭与 click 双触发 |
| 图标用 lucide-react | 线性 stroke 风格与手写 SVG 同源，免维护路径；新图标一律从库取 |
| 学习周报：确定性聚合，零模型调用 | 周报数据全部来自 SQL 聚合（提问/作答/误区/日程完成/掌握度快照），可复现、零成本；`mastery_snapshots` 每周首请求落快照，delta = 现值 − 上周快照 |
| Embedding 可插拔 + 故障降级 | 主模型 DeepSeek 没有 /embeddings——向量服务独立配（`ZHIJI_EMBEDDING_BASE_URL/KEY`，推荐智谱 embedding-3 / 硅基流动 bge-m3）；向量服务挂了自动降级纯关键词，入库/问答不中断 |
| 检索四路加权融合（原查询 FTS 1.0 / 扩写 FTS 0.5 / 短词 LIKE 0.8 / 向量 1.0） | 同义扩写是**推断**出来的召回，与字面命中平起平坐会把噪声顶上去；短词 LIKE 按覆盖度排序、精确度较高故居中。RRF 加 `weights` 参数即为此，默认全 1.0 向后兼容 |
| 同义词表内置但保守，可经 JSON 追加 | 只收无歧义等价词（中文异名 + 中英对照）；多扩污染精确率，而少扩只是少一路兜底——其他三路仍能命中。表是纯数据、匹配是纯函数，零模型调用且确定性，评测可稳定复现 |
| 两字词走 LIKE 路而非硬塞进 FTS | trigram 物理上索引不了 <3 字符，而中文核心学科术语大量是两字（矩阵 / 秩 / 导数 / 概率 / 队列）。按**命中覆盖数**排序近似于小 BM25，覆盖多的片段自然排前，单命中也保留机会 |
| 过程流"有工具调用才默认展开" | 纯聊天回合展开会显得啰嗦；有工具才有可看的执行链 |
| 全站页面过渡统一为「退场 200ms → 入场 200ms」 | 规范由用户钦定：ease-out、4px 位移、无缩放；实现 = main 以 pathname 为 key remount（入场）+ 全局拦截站内点击先播退场再 push；首屏/刷新不播（prevPathRef 派生，勿改回 effect 置位的模块标记——StrictMode 双跑会破）；连点重置计时器最后一次为准；prefers-reduced-motion 关闭 |
| 「全部记忆」视图按内容去重 | 记忆唯一约束是 (user, project, content)，同一事实在多个课程各存一份；合并展示必须去重，且前端 key 用 id 不用 content |
| 长名字用省略号不用渐变淡出 | mask 方案在用户浏览器不可靠，用户拍板用"…" |
| 日程「一键安排」用确定性算法而非模型 | 结果可预期、可复现、零成本；同一天同一堆任务结果恒定 |
| 日程时间轴固定 06:00–24:00 | 学生作息；刻度位置稳定，滚动不跳 |
| 笔记页右栏内联折叠，不做浮层遮罩 | 遮罩会让正文"变黑"，阅读型页面不该抢层 |
| 保留 `graph.py` 自写 tools 节点 | 权限与 HITL 决策要留在自己手里（不用 LangGraph ToolNode） |
| 品牌标识用线性 SVG 图标，不用色块/emoji | 用户明确偏好（见全局记忆） |
| 私教人格：总纲（三条红线 + 输出规格 + 技术过程内隐 + 禁止清单）全角色共享，分场景骨架挂各自角色 | 总纲是"私教底线"，所有人都得守；骨架是角色的活（讲解/错题归 tutor、规划归 progress），混在一起会让出题角色也去讲"概念四层"，串味 |
| 「技术过程内隐」= 提示词声明 + **执行层兜底拦内部工具标识符** | 提示词只是劝告，项目承诺"由执行层强制"——工具标识符在教学正文里永远不会合法出现，是能客观判定的子集；只拦标识符（`knowledge_search` 等），不拦「计算器」「检索」这类口语词 |
| 过程流面板保留，只让**回复语气**内隐 | 用户拍板：面板是产品卖点（可看到思考/工具链），技术细节该在面板里、不该在回复正文里；两者不冲突 |
| 工作区路径一律 resolve 成**绝对路径**再比 | 相对/绝对混用会让 `relative_to()` 在写入**之后**抛错，症状是"文件在、却报写入失败"；统一绝对路径后 `_safe_resolve` 的越界判定也才有意义（resolve 会展开符号链接） |
| `user_id` 压成单层目录名（白名单 + 去首尾点） | 它是客户端可传的，直接当路径段用能穿越出工作区；压成单层后 `data/workspace/<user_id>/` 的隔离才成立 |
| 删除一律**级联**（误区→派生题、资料/库→引用其片段的题、项目→记忆+会话+检查点） | 本项目没有外键，级联全靠手写 SQL；留悬挂引用会让"已删的东西"继续出现在今日复习/记忆列表里，比报错更难发现。判据一句话："它被删了，谁还指着它？" |
| UNIQUE 冲突在**接口层**翻译成 409（不是 500） | `sqlite3.IntegrityError` 冒到接口层就是 500 且日志里只有堆栈；用户看到的应该是"同名项目已存在"。三处唯一约束（projects / practice_questions / memories）都要按此处理 |
| 同一资源的归属校验**状态码统一 404** | 会话 GET messages 曾"200 + 空列表"、PUT/DELETE 却 404，调用方无法区分"没消息"与"不是你的会话"；统一成 404 后语义一致，且不泄露任何数据 |
| 删会话顺带清 LangGraph 检查点线程 | 检查点与会话是两套存储，只删 `chat_sessions` 会让"已删对话"仍能从孤儿线程还原正文；清理前确认无其他会话共享该 thread_id（thread_id 是客户端传的） |
