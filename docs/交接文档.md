## 一、这个项目是什么（自包含简介）

**StudyGraph 是一个面向大学生的 AI 学习助手**，Web 优先（Next.js 前端 + FastAPI 后端 +
SQLite）。它围绕一个真实痛点构建：**作业散落在各个课程系统里，平时不整理，期末就没有题可复习**——
所以核心不是"更会聊天"，而是**把学科知识库做成平时的沉淀罐，期末从库里长出复习材料**。

技术上，它用 **LangGraph** 把"一次学习回合"做成一张显式状态图
（`route → plan → agent ⇄ tools`），并配齐一套 Agent 工程模块：
意图路由、工具最小权限、人在环、护栏、工具可靠性、上下文压缩、规划、模型路由、
成本控制、MCP、评测门禁、回合 trace。后端按**洋葱/六边形**分层。

**项目定位**：作为**全国大学生数字媒体科技作品及创意竞赛（赛道十三：智慧教育与智能软件类）**
的参赛作品。一切决策以"能否交付、能否演示、材料能否与代码对上"为准。

## 六、架构速览与关键代码入口

```text

                                  ↓
                            基础设施层(SQLite/Embedding/LLM/MCP)
```

```text
START → route(意图路由) → plan(复杂请求才规划) → agent(模型+工具循环) ⇄ tools → END
```

## 九、已知限制与坑（完整清单）

- **自动测试必须走 Mock**：`uv run pytest -q` 零 API 消耗；不要引入读真实 Key 的测试。
- **从节点里同步写 SQLite 会阻塞事件循环**，导致检查点连接无法释放锁（`database is locked`）。
  正确做法：写库走 `asyncio.to_thread`，连接开 **WAL + busy_timeout**（已修，别回退）。
- **HITL 的 `GraphInterrupt` 不能被 `try/except Exception` 吞掉**：`tools` 节点里必须
  `except GraphInterrupt: raise`，否则人在环失效。
- **HITL 依赖检查点**：图必须编译时带 `checkpointer`，否则 `interrupt()` 无效。
- **推理型模型输出预算**：真实模型务必设 `STUDYGRAPH_MAX_OUTPUT_TOKENS=4096`，
  否则"思考"会吃光预算导致空回答。
- **Next 16 `cacheComponents`**：预渲染期禁止 `Math.random()`；随机值放 `useEffect`/`useRef`。
- **React 19 ESLint**：`react-hooks/set-state-in-effect`（挂载拉数据要 `// eslint-disable-next-line`）、
  `react/no-unescaped-entities`（JSX 文本里别用直引号，用「」）。
- **Python 字符串里的中文引号**：内层引号用「」，别用 ASCII `"`（会打断字符串）。
- **入口点**：后端 `studygraph.interfaces.api:app`；控制台脚本 `studygraph` / `studygraph-demo`
  / `studygraph-eval` / `studygraph-trace`。
- **数据安全**：`data/` 与 `.env` 被 Git 忽略；**不要**打印或提交任何 Key/密码，不要删 `data/` 下数据。

## 十、开发规则（必须遵守）

```text
明确用户场景 → 代码 → 自动测试(Mock,零 API 消耗) → 浏览器/API 验证
→ 更新文档(README/架构/使用指南/参赛材料) → ruff + pytest + 前端 lint/build → commit → push
```

- 提交规范：`feat:` 功能与测试；`docs:` 文档与材料。
- 推送：`git push`（本机已配置 GitHub 凭据）。
- **绝不**：无验证声称完成、绕过评测门禁、把计划写成已完成、泄露 Secret。
- 前端改动后必须 `cd frontend && npm run lint && npm run build`。
