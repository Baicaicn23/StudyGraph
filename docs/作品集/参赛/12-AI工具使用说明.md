## 二、主要 AI 工具及使用情况

| 工具／模型 | 使用环节 | AI 主要用途或产出 | 学生后续处理 |
| --- | --- | --- | --- |
| AI 编程助手（Claude Code / CodeBuddy 一类） | 后端开发 | 依分层架构与端口 Protocol 生成函数级代码骨架、类型注解、异常处理分支 | 逐文件审阅并重写实现；核对依赖方向是否真的只朝内；按项目既有约定统一命名与注释风格 |

| AI 编程助手 | 前端开发 | 生成 React 组件与样式初稿 | 重构组件结构；按实际接口返回结构调整状态管理；统一交互反馈与空状态处理 |
| AI 编程助手 | 文档撰写 | 起草架构说明、使用指南、参赛材料初稿 | 逐条核对与代码的一致性；删除"计划中"却写成"已完成"的表述；补齐每个数字的出处 |
| AI 编程助手 | 调试辅助 | 分析报错栈、给出可能成因与排查方向 | 由学生亲自复现、定位根因并修复；AI 给出的猜测若与实际不符则弃用 |
| 大语言模型 API（可选，运行时） | 作品运行时的讲解、错题归因、出题 | 生成自然语言讲解与题目 | 不涉及——这是**作品的功能本身**，学生在编码阶段固定了提示词与教学人格规则 |

## 三、代表性 AI 使用过程

### 3.1 环节一 · 检索层的四路召回与权重复核

| 项目 | 具体内容 |
| --- | --- |
| 使用环节及目的 | 实现中文资料检索，并排查"某些同义词题目召回失败"的问题 |
| 主要工具／模型 | AI 编程助手（代码生成与调试辅助） |
| 主要输入或素材来源 | 21 篇自编中文语料 + 35 个带标注的问题；项目既有的检索实现 |
| AI 主要输出 | 四路召回的实现草案、RRF 融合与词面精排的代码、以及针对"同义题漏召回"的多条成因假设 |
| 学生筛选、修改或再创作 | **逐条验证每个假设**：将语料与题库手工过一遍，构造最小复现用例（"本征值"这类同义表述），跑评测定位到真正原因——评测所用向量实现的哈希在共享 n-gram 上相互抵消，使向量路退化为纯噪声，并以 1.0 权重挤掉真正命中的候选。修复方式是更换评测用嵌入实现（改为 +1 计数哈希），并保留原实现供生产环境使用 |
| 最终成果中的应用位置 | `infrastructure/embeddings.py` 的评测嵌入实现；`domain/retrieval.py` 的融合权重；评测基线 JSON 随之重算 |
| 可核验材料 | 《评测证据包》第二节的复现命令与实际输出；修复前后 MRR 对比 |

**这一环节的边界**：AI 提供了假设清单，**根因由学生构造用例定位**，修复方案与验证由学生完成。

### 3.2 环节二 · 教学人格分层与提示词结构

## 五、学生原创贡献说明

### 学生自主完成的核心工作

- **需求分析**：从自身复习经历定位问题，确定"资料 → 错题 → 复习"主线，并**主动放弃**鉴权、多租户等外围功能。
- **架构设计**：四层洋葱架构与端口 Protocol 的划分；回合状态图（route → plan → agent ⇄ tools）与四道权限闸门（模型提议 / schema 白名单 / 执行层判定 / 人在环）的设计；检索四路通道与权重体系（1.0 / 0.5 / 0.8 / 1.0）。
- **程序开发**：全部后端（domain / application / infrastructure / interfaces 四层）与前端（Next.js 16，7 个路由）代码；284 项测试；评测工具链（`zhiji-eval` / `zhiji-trace`）；演示数据播种脚本；演示素材生成脚本。
- **内容创作**：5 学科 15 份复习笔记、4 份 PDF 讲义 / 3 份 Word 笔记 / 2 份 PPT 课件 / 2 张示意图的全部正文；检索 35 题与意图 15 句的全部标注；作品的名称与标识。
- **模型适配**：教学人格分层设计、深度思考档位固定、模型路由规则、token 预算闸门。
- **测试优化**：设计消融对照（关掉词面精排看 MRR 变化）证明机制有效；定位并修复评测嵌入实现的哈希抵消缺陷；依据测试结果重构检索融合逻辑。
- **系统集成**：前后端联调与 SSE 事件协议、检查点与会话级联清理规则、跨页面状态一致性。
- **成果表达**：作品介绍文档、运行说明、汇报 PPT 与视频的结构与全部事实核对。

### AI 与学生工作边界说明

本项目中 AI 工具的角色是**编码与写作的辅助工具**，不构成作品的技术组成部分。具体边界：

1. **AI 不参与架构决策**——四层划分、状态图结构、权限闸门设计、检索通道与权重取值均由学生确定。
2. **AI 不产生任何评测数字**——检索 Hit@3 / MRR 0.9714、消融 0.9571、意图准确率 1.0、284 项测试通过，全部由学生在本机运行命令得出，原始命令与输出随材料提供，可原样复现。
3. **AI 不生成评测标注**——35 题检索考卷与 15 句意图样本由学生逐条手工标注。
4. **AI 不生成作品中的任何视觉素材**——视频画面由学生用代码绘制，界面证据为实机截图。
5. **AI 产出的每一处代码都经学生审阅与重写**，并由测试与评测门禁验证；未通过验证的 AI 产出被弃用（例如初版检索融合逻辑因未考虑向量权重挤占问题而被推翻重写）。
