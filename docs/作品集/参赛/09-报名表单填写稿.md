## 先看套路：三篇获奖简介的写法拆解

样本：抑郁症筛查系统（约 1100 字）、竞赛推荐系统（约 1300 字）、步态识别身份认证（约 200 字）。

| # | 套路 | 样本里的原样 |
| --- | --- | --- |
| 1 | **第一句就定性** | 三篇开头都是「本产品 / 本系统 / 本作品 + 是针对 X 的 Y 系统」，一句话说完"给谁、做什么" |
| 2 | **先声明叙述结构** | "下面将通过**设计方式、使用方法和作品优点**三方面来对产品进行描述"——先告诉评审这篇怎么组织 |
| 3 | **技术单列一节，写满** | "设计方式"篇幅最大，**框架名、模型名、数据库全在正文里**：Django、CNN-BiLSTM、PC-DRN、GlobalPointer、React + Next.js、SpringBoot + MyBatisPlus、MySQL |
| 4 | **使用方法写成操作流** | 从用户动作写起："佩戴脑电环 → 蓝牙接收器接入电脑 → 打开开关 → 点开始入睡 → 点睡眠报告 → 点查看更多" |
| 5 | **优点先讲现状痛点** | "目前抑郁症的诊断主要基于医生访谈和问卷，缺少客观标准……漏诊、误诊概率大" → 再说本产品能做到什么 |
| 6 | **功能按角色分条** | "①学生 ②辅导员 ③专业教师"逐条列各自功能 |
| 7 | **结尾落到社会价值** | "减少抑郁症给患者带来的痛苦、给社会带来的负担""助力智慧教育的发展与建设" |

**三条结论（其中两条修正了我之前的判断）**：

1. **框架名该放哪，这下清楚了**：名字里只写**能力维度**（多模态 / 深度学习），**框架名写在简介正文里**——样本中 Django、SpringBoot、MySQL 一个不落。所以我们的 LangGraph / FastAPI / Next.js / SQLite 写进简介不是"暴露实现细节"，而是**应有之义**。
2. **简介可以很长**：偏工程的作品都写到千字以上，且**不加小标题、正文连排**。之前我给的那版 533 字是"产品文案腔"，其实偏短了。
3. **语言是申报书腔，不是产品文案腔**：长句多、"为实现以上功能""与此同时""不仅如此"这类连接词密集，技术名词**不解释**（默认评审看得懂）。样本里甚至有错别字和重复词——说明评审判的是**内容密度**，不是文字打磨。

## 3、作品简介

### 申报书腔完整版（1432 字 · 推荐，最贴近获奖样本）

> ⚠️ **第一句的定位词要跟最终作品名一致**（这里暂用「AI 学习助手系统」）。作品名定稿后把这里回填成同一个说法——简介与作品名对不上，是前置审查会看的不一致。

本作品是针对在校大学生"学习资料散落、期末无题可复习"这一普遍问题所设计的 AI 学习助手系统，以学科知识库作为平时的沉淀载体，在期末自动生成可练习的复习材料。下面将通过设计方式、使用方法和作品优点三方面对本作品进行描述。

1. 设计方式
本作品采用大模型智能体编排与混合检索相结合的方式实现，具体内容如下（细节可参见作品说明材料）：
（1）面向学习回合的智能体编排。将一次学习会话建模为显式状态图（意图路由 → 规划 → 模型与工具循环），并基于 SQLite 检查点实现断点续跑与人工介入（HITL）：所有写操作必须先由用户确认才能落库，使"AI 不擅自改动用户数据"成为执行层强制而非提示词劝告。
（2）学科知识库与混合检索。检索由 FTS5 trigram 中文全文检索、向量余弦相似度、同义词扩写与两字词 LIKE 四路召回构成，并按 RRF 加权融合排序；资料支持 PDF / Word / PPT / Excel 原样秒传与懒解析，PDF 与 PPT 按页切块并保留页码出处。
（3）学习闭环与掌握度建模。错题按错误类型（概念混淆 / 步骤遗漏 / 条件误读 / 计算失误 / 表述不清）归档，并据此生成变式题；作答自评后按间隔重复算法更新复习排期与学科掌握度。
（4）Agent 工程模块。包括工具最小权限（接口层与执行层双重校验）、输入输出护栏、工具超时与有限退避重试、上下文压缩、模型路由与 token 成本控制、MCP 外部工具接入，以及检索与意图的固定评测门禁与回合诊断。
（5）系统实现。后端采用 FastAPI + SSE 流式接口，前端采用 Next.js，全部业务数据存储于单个 SQLite 文件，可随文件整体迁移，无需独立数据库服务。

2. 使用方法
用户打开系统后，先在"知识库"中按学科建立资料库，可直接上传 PDF / Word / PPT 讲义，也可将拍摄的板书照片交由多模态模型转写为文字后入库。随后在对话界面提出问题，系统基于自有资料作答并标注出处；当涉及保存笔记等写操作时，系统会先弹出确认框，用户确认后才写入知识库。
在"错题练习"中，用户记录错因并选择错误类型，点击"出变式题"即可由模型针对该错因生成新题；作答完成后可查看参考答案与关键步骤，并按"又忘了 / 有点难 / 掌握了 / 太简单"四档自评，系统据此更新掌握度与下次复习时间。
在"今日复习"中，用户可查看当天到期题目、薄弱学科与近期新增误区，并按建议展开复习；在"日程"中把学习计划排入时间轴，或先放入收件箱稍后再排。

3. 作品优点
目前大学生复习普遍缺乏可持续的资料积累机制：作业与讲义分散在各课程平台与聊天工具中，平时没有整理动力，到期末则无题可练；与此同时，大模型应用普遍存在"黑盒"问题——用户无法判断答案依据何在，也无法确认系统是否会擅自改动自己的数据；此外，各课程系统之间彼此孤立，学生难以获得跨学科的掌握度视图。
针对上述问题，本作品从三方面作出改进：其一，把知识库从"搜索用的资料夹"重新定位为"期末复习的原料库"，使日常碎片自然沉淀为可出题的材料；其二，将 AI 的执行过程做成可见、可复现、可中断的显式流程，写操作强制人工确认；其三，为检索与意图建立固定评测基线，使系统能力可被度量而非仅凭主观感受——当前全项目 284 项自动化测试全部离线通过，检索 35 题考卷 Hit@3 = MRR = 0.9714（接真实向量 35/35 全中）、意图 15 句准确率 = 1.0。
本作品有助于智慧教育的落地：让每一位学生都拥有一个可持续积累、过程可信赖的学习助手，把"期末临时找题"变为"平时自然沉淀"，从而提升复习效率与学习质量。

### 中等版（522 字 · 表单限 600～800 字时用）

「知迹」是一个面向大学生的 AI 学习助手（Web 应用）。它针对一个具体痛点：**作业与讲义散落在各个课程平台与聊天工具里，平时没有整理的动力，等到期末想复习时，题和资料都已经找不回来。** 因此它的核心不是"更会聊天"，而是把**学科知识库做成平时的沉淀罐**——期末从库里长出复习材料。

它做这些事：按学科沉淀资料（PDF / Word / PPT / Excel 秒传并按页解析、拍照的板书由多模态模型转写成文字、也可直接手写笔记），基于自己的资料问答并**标注出处**；把错因记成带「错误类型」的错题，据此生成**变式题**，作答后可查看参考答案与关键步骤，并按自评更新掌握度、安排下次复习；再用「今日复习」汇总到期题、薄弱学科与近期误区，用「日程」安排什么时候做。

技术上，后端用 **LangGraph** 把一次学习回合做成**显式状态图**（意图路由 → 规划 → 模型与工具循环），并配齐 Agent 工程模块：工具最小权限（接口层与执行层双重校验）、**人在环**（写操作必须用户确认）、输入输出护栏、工具超时与重试、上下文压缩、模型路由与 token 成本控制、MCP 外部工具接入，以及检索与意图的**固定评测门禁**与回合诊断。全项目 **284 项自动化测试**（全程离线、零 API 消耗），检索 35 题考卷 Hit@3 = MRR = 0.9714、意图 15 句准确率 = 1.0。

## 4、创意来源（必填 · 全文 489 字）

随着教育数字化与智慧教育的推进，学生的学习资料与练习需求日益分散在多个平台，而现有工具大多只解决"问答"这一环，缺少把日常积累与期末复习连起来的机制。本作品的创意来自团队自己在期末复习中的共同经历：课程作业、讲义和答疑记录分散在多个教学平台与聊天工具里，平时没有整理的动力，等想复习时，"题"和"资料"都已经找不回来了。我们意识到缺的并不是一个更聪明的问答机器人，而是**一个把日常碎片自动攒成复习材料的沉淀系统**——于是把"知识库"从"搜索用的资料夹"重新定位成"期末复习的原料库"。

第二个来源是对"AI 黑盒"的不信任：大模型给出答案时，用户无法判断它查了什么、有没有依据、会不会擅自改动自己的数据。因此我们把一次学习回合做成**显式的状态图**——意图判断、检索、工具调用、人工确认都是可见、可复现、可中断的步骤，**写操作必须经用户确认才落库**；再结合苏格拉底式引导与掌握度自适应，让它更接近"私教"而不是"答案机"。

在定位上，作品对应赛道「智慧教育与智能软件类」：既要解决真实学习场景里的问题，也要把 Agent 工程能力做成**可评测、可解释**的软件，而不是一个演示用的壳。

## 5、运行环境（必填 · 按本机实测填写）

**说明**：本项目是**单机本地运行**的 Web 应用，一条命令同时启动前后端，全部数据存于单个 SQLite 文件，**不需要单独安装数据库服务**。以下为本机（演示与开发环境）实测配置。

- **操作系统**：macOS 27.0.1（MacBook Pro，Apple M2 Pro 芯片，10 核 CPU）
- **内存 / 磁盘**：16 GB 内存；可用磁盘 342 GB
- **后端运行时**：Python 3.12.10（依赖与虚拟环境由 uv 0.12.19 管理）
- **前端运行时**：Node.js v22.22.2
- **数据库**：SQLite（Python 内置，随项目自动创建，无需独立服务）
- **浏览器**：Google Chrome 155（演示窗口 1440×900）
- **核心框架**：LangGraph 1.2.14、FastAPI 0.142.4、Next.js 16.4.0、React 19.3.0、Tailwind CSS 4
- **大模型**：可接入任意 OpenAI 兼容接口（演示使用 DeepSeek-V4.1-Flash）；向量检索可接入任意 OpenAI 兼容 Embeddings（演示使用智谱 embedding-3）；**未配置模型时可切换内置 Mock 模型完全离线运行**（自动化测试即走此模式，零 API 消耗）
- **常用软件**：macOS 预览（看图）、QuickTime Player（录屏）、iMovie（剪辑，系统自带）
- **网络**：检索与大模型调用需联网；离线时可运行全部内置演示数据与工程验证（测试与评测均离线）
