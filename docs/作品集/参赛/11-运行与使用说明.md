# 运行与使用说明

**作品名称**：知迹 —— 会整理、会出题的学习 Agent
**适用对象**：评审专家 / 测试人员

本项目是**单机本地运行**的 Web 应用：一条命令同时启动前后端，全部业务数据存于单个 SQLite 文件，不需要单独安装数据库服务。

---

## 一、环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | macOS / Linux / Windows | 已在 macOS 27.0.1（Apple M2 Pro）实测 |
| Python | 3.12 及以上 | 依赖与虚拟环境由 [uv](https://docs.astral.sh/uv/) 管理 |
| Node.js | 18 及以上 | 已在 v22.22.2 实测 |
| 数据库 | 无需安装 | SQLite 随 Python 内置，首次运行自动创建 |
| 网络 | **不需要** | 默认 Mock 模型，全离线可用、零 API 消耗 |

**核心框架版本**（本机实测）：LangGraph 1.2.14、FastAPI 0.142.4、Next.js 16.4.0、React 19.3.0、Tailwind CSS 4。

---

## 二、安装

```bash
cd 知迹_工程源码

# 后端依赖（含可选的 openai 适配层；测试需要它）
uv sync --extra openai

# 前端依赖
cd frontend && npm install && cd ..
```

> `uv sync --extra openai` 中的 extra 用于让测试用例能构造 OpenAI 兼容的模型桩。
> **若只跑 Mock 演示**，`uv sync` 亦可；但完整跑测试请带上 `--extra openai`。

---

## 三、启动

```bash
./scripts/dev.sh
```

启动后：

| 服务 | 地址 |
| --- | --- |
| 前端界面 | <http://localhost:3000> |
| 后端接口 | <http://127.0.0.1:8011> |
| 健康检查 | `curl http://127.0.0.1:8011/api/health` |

> ⚠️ 后端**没有热重载**。修改后端代码后需重启进程。
> 脚本默认使用内置 Mock 模型（零成本、不联网）；若需接入真实模型，见第六节。

### 3.1 播种演示数据

首次使用建议先播种，可立刻看到有内容的界面（**不会消耗任何 API 额度**）：

```bash
uv run zhiji-demo --reset
```

将创建：5 个学科知识库、24 份自编资料、5 门课程、7 条典型误区、若干错题与日程条目。

> ⚠️ `--reset` 会**清空并重建**数据库。真实使用前请先备份（见第六节）。

## 四、命令行用法（无需启动 Web）

```bash
# 聊天（终端里直接问）
uv run zhiji "帮我算一下 7 * 9"

# 沉淀一条笔记 —— 写操作会先请求确认（--yes 可自动同意）
uv run zhiji "记住：我在准备月底的微积分测验" --yes

# 检索刚沉淀的内容
uv run zhiji "我的笔记里怎么讲微积分测验的？"
```

预期输出示例：

```text
（模拟模型）根据工具返回的结果：63
```

这条命令背后：意图被识别为「计算」→ 路由到计算子智能体 → 模型请求调用计算器工具（参数 `7 * 9`）→ 工具返回 `63` → 模型据此作答。

## 五、验证与评测（推荐评审专家执行）

全部命令**离线运行、零 API 消耗**，是验证本作品可度量性的最快路径。

### 5.1 自动化测试

```bash
uv run pytest -q --basetemp=/tmp/sg-pytest
```

预期：`284 passed`。全部使用 Mock，不联网、不消耗额度。

> `--basetemp` 指定临时目录；macOS 上建议保留该参数，避免与系统临时目录权限冲突。

### 5.2 代码规范检查

```bash
uv run ruff check src tests scripts
cd frontend && npx tsc --noEmit && npx eslint src && cd ..
```

### 5.3 检索评测

```bash
uv run zhiji-eval retrieval \
  --dataset evals/datasets/retrieval.json \
  --baseline evals/baselines/retrieval.json
```

预期输出：

```text
== retrieval 评测 ==
  cases: 35
  k: 3
  hit_at_k: 0.9714
  mrr: 0.9714
  ✓ 无回归
```

**消融对照**（关掉词面精排，机制有没有用当场可见）：

```bash
uv run zhiji-eval retrieval --dataset evals/datasets/retrieval.json \
  --baseline evals/baselines/retrieval.json --no-rerank
```

预期：`mrr: 0.9571`（较开启时下降）。

### 5.4 意图分类评测

```bash
uv run zhiji-eval intent \
  --dataset evals/datasets/intent.json \
  --baseline evals/baselines/intent.json
```

预期：`cases: 15`、`accuracy: 1.0`。

> **回归门禁**：指标掉出容差（0.05）时命令**退出码为 1**，可直接进 CI 拦截回归。

### 5.5 回合诊断

```bash
uv run zhiji-trace --thread <thread_id>
```

把一次会话读成诊断树，并归因到责任层（检索 / 工具 / 模型 / ok）——"失败了"之外，还能指出该改哪一层。

## 六、可选：接入真实模型

任何 OpenAI 兼容平台（DeepSeek / OpenAI / …）均可。配置写进项目根目录 `.env`（该文件已随工程附带示例，实际密钥请自行填写，**不要提交到任何仓库**）：

```bash
ZHIJI_LLM_PROVIDER=openai
ZHIJI_MODEL=deepseek-flash
ZHIJI_OPENAI_BASE_URL=https://api.deepseek.com/v1
ZHIJI_OPENAI_API_KEY=你的密钥
ZHIJI_MAX_OUTPUT_TOKENS=4096
```

启动后端时需显式指定 provider（脚本默认走 Mock）：

```bash
ZHIJI_LLM_PROVIDER=openai ./scripts/dev.sh
```

> ⚠️ 推理型模型务必设 `ZHIJI_MAX_OUTPUT_TOKENS=4096`，否则输出会被"思考"吃光导致空回答。
> 完整环境变量清单见工程内的 `.env.example`。

## 七、数据与备份

- 全部业务数据位于 `data/zhiji.db`（单个 SQLite 文件）及其同目录的附件目录，可整体复制迁移。
- 备份示例：

```bash
cp data/zhiji.db data/backups/zhiji-$(date +%Y%m%d).db
```

- 重建演示数据：`uv run zhiji-demo --reset`（**会清空现有数据**）。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 页面空白、没有任何数据 | 后端未启动。先 `lsof -nP -iTCP:8011 -sTCP:LISTEN` 确认，再看后端日志 |
| 启动脚本报模型相关错误 | 脚本默认 Mock；接真实模型需显式 `ZHIJI_LLM_PROVIDER=openai ./scripts/dev.sh` |
| 修改后端代码不生效 | 后端无热重载，需重启进程 |
| 测试报 `No module named 'langchain_openai'` | 安装时漏了 extra，补 `uv sync --extra openai` |
| pytest 报临时目录权限错误 | 加上 `--basetemp=/tmp/sg-pytest` |
| 界面文字与本文档不一致 | 以工程内 `README.md` 与 `docs/使用指南.md` 为准 |
