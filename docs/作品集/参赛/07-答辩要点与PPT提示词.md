# 07 · 答辩要点与 PPT 提示词

## 一、三分钟陈述稿

> **口径提醒**：知迹 = **整理学习资料 ＋ 自动出错题 ＋ 结合知识库复习**。
> 讲的时候按这三件事展开，工程内容（权限 / 可恢复 / 门禁 / 评测）只作为**支撑**出现。

1. **它是什么**：知迹是一个个人学习管理台，做三件事 —— 整理学习资料、自动出错题、
   结合知识库复习。资料进去，题出来，复习排好。
2. **为什么这么设计**：学习是连续的过程，工具却常是一次性的 —— 资料被存下、答案被说过、
   错题被标过，都没变成下次还能用的东西。所以知迹把一次学习回合做成一张
   **可恢复、可拦截、可度量**的状态图。
3. **怎么做的**：用 **LangGraph** 把回合拆成 `route → plan → agent ⇄ tools` 四个节点，
   每个节点都有名字和位置；资料侧走四路混合检索；工具侧做双层权限 + 写入前人工确认。
4. **最值得讲的三个点**：
   - **工具最小权限双层** —— schema 层看不见，执行层拦得住；
   - **写入前先问一句** —— "AI 不改你的数据"是执行层的强制承诺，不是提示词里的请求；
   - **可评测** —— 检索 35 题 / 意图 15 句各有基线，改动可量化，消融能当场看到差异。
5. **证据**：284 项自动测试全绿；检索 Hit@3 = MRR = 0.9714（35 题），接真实向量 35/35 全中；
   意图准确率 1.0；关掉词面精排 MRR 掉到 0.9571；trace 可归因到层。

## 三、追问预案（Q&A）

**Q：为什么不用现成 Agent 框架，而是自己搭？**
A：我需要的是"控制权"——工具权限、人在环、预算、评测都要能自己决定。用 LangGraph
拿到的正是**编排能力**（状态图 + 检查点 + 中断），同时把决策留在自己手里；这不是
"不用框架"，而是"框架负责编排、我负责决策"。

**Q：工具最小权限为什么要做两层？**
A：只做 schema 层，模型仍可能"说出"被禁工具名并失败；只做执行层，模型会反复尝试、
浪费轮数。两层缺一不可，才能让"练习 agent 只读、进度 agent 无工具"成为**执行层的
强制承诺**。

**Q：人在环（HITL）是怎么实现的？**
A：用 LangGraph 的 `interrupt()` 在写操作前暂停图，用户确认后用 `Command(resume=...)`
从**检查点**恢复。它依赖持久化，正好也验证了断点续跑能力。

**Q：怎么证明系统没变差？**
A：检索与意图有固定考卷 + 基线 JSON，改动后重跑，掉超过容差命令就返回非零（可进 CI）。
更直接的是**消融**：关掉词面精排，MRR 从 0.9714 掉到 0.9571 —— 机制有没有用当场可见，
不用靠"我觉得挺好"。

**Q：成本怎么控制？**
A：每次调用记 token，支持按日预算，超限阻止真实调用；并按复杂度做**模型路由**（小模型
接简单意图）。默认 Mock，演示零成本。

**Q：MCP 是什么？**
A：Model Context Protocol，连接外部工具的标准协议。我自写了最小 stdio JSON-RPC 客户端，
能启动外部 server、发现工具并注册进工具表——所以作品能"即插即用"外部能力。

**Q：为什么用 SQLite，不上 MySQL？**
A：这是**主动选型**。本项目单用户 + 单机演示，服务端库的并发写优势用不上；换过去会
重创检索层（FTS5 trigram 换 ngram、四路召回与评测基线全部重新标定），也会让离线演示变脆。
一个文件就是全部数据，零运维、可离线、可评测，端口化留了升级路径。分水岭是出现
多写并发或多机部署 —— 真到那天我会优先 Postgres（`pg_trgm` + `zhparser` + `pgvector`）。

**Q：当前边界？**
A：六项能力里**两项达标、三项一半、一项没做**，我主动说：
- **没做**：任务级成功率评测（现有考卷只测"找到没""分类对不对"，不测"这次复习有没有用"）；
- **一半**：工具执行治理（缺参数级细粒度约束）、长上下文管理（缺关键事实外置）、
  长期记忆（缺过期/替换/删除机制）；
- 另外**多用户与数据隔离、在线监控聚合面板、Reranker 重排、反思式自我批判**也标为「计划中」。
这些在 [02-主张与证据核对表](02-主张与证据核对表.md) 里都有据可查，**不以已完成口径出现**。
（多模态发图与出题难度分层**已经做了**，见 02 与演示脚本，别再说成"尚未做"。）

**Q：和已有作品会不会重复？**
A：本项目为独立实现（独立仓库、独立架构与代码）；是否与他作构成重复参赛，以团队与
赛事规定为准（见 [05](05-来源与授权清单.md) §五）。
