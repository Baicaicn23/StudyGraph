## 零、开工前必须知道的 5 件事

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **标题文字可以直接写进图里** | 豆包 / Seedream 4.0 的**中文渲染准确率约 98%**，标题、副标题、标签都能清晰无误地生成。本文档的每页提示词都已把该页标题**原样写进提示词**，生成时会直接印在图上。 |
| 2 | **但数字不要交给模型写** | 比例、分数、版本号、日期这类**只要有一个数字错就是硬伤**（0.9714 写成 0.9714 差一位、0.9571 写成 0.9751 就成了编造）。这些一律**留在 PPT 里用文本框叠**。 |
| 3 | **一张图只讲一件事** | 每页配图对应页内一个论点，不做"一张图塞十个信息"的合成大图。 |
| 4 | **全部浅色调** | 白 / 米白 / 浅灰底 + 柔和顶光。深色系会跟 PPT 主题打架，也跟「知识整理」这种场景违和。 |
| 5 | **真实质感，不要扁平矢量** | 3D 写实渲染 / 摄影级质感。扁平插画、扁平图标、线框图一律不要。 |
| 6 | **不放人物（除封面与场景页）** | AI 生成的人脸是答辩事故高发区。除封面剪影与"一周日常"页外，**一律不出现人物**。 |

**统一生图参数**（每页都一样，只改提示词内容）：

- 比例：**16:9**（PPT 默认画布）；单页特写用 **1:1** 或 **4:3**
- 建议尺寸：**≥ 1920×1080**（豆包若给 2K/4K 更佳，投屏不虚）
- 质量：最高档
- 每页生成 **3–4 张候选**，挑一张构图最干净的

## 一、整份 PPT 的叙事骨架

### 1.1 四段推进（这就是全篇顺序的依据）

```
第一段  它是什么、给谁用          p01 – p04
        ↓  从"想要"过渡到"怎么做"
第二段  三件事怎么被做稳          p05 – p10
        ↓  从"单个能力"过渡到"整套治理"
第三段  看不见的三件事 + 怎么证明  p11 – p13
        ↓  从"能跑"过渡到"边界在哪"
第四段  边界与收束                p14 – p16
```

### 1.2 一句话说清每段在干什么

| 段 | 页码 | 这一段唯一要让人记住的 |
| --- | --- | --- |
| 一 | p01–p04 | 这是一个把资料变成题、再变成复习计划的应用 |
| 二 | p05–p10 | 每一件事都不是"调用一次 API"，而是可恢复、可拦截、可缓存的流程 |
| 三 | p11–p13 | 除了用户看得见的功能，还有三件看不见但在撑住它的事；以及怎么证明没坏 |
| 四 | p14–p16 | 哪些做成了、哪些只做了一半、哪些没做；下一步补什么 |

### 1.3 页与页之间的衔接句（讲的时候念出来，PPT 上不用写）

| 从 → 到 | 过渡句 |
| --- | --- |
| p01 → p02 | "先说清楚它做什么，再说怎么做的。" |
| p02 → p03 | "先看产品本身。" |
| p03 → p04 | "这三件事在一周里是怎么串起来的。" |
| p04 → p05 | "看得见的部分讲完了。接下来是让它靠得住的部分。" |
| p05 → p06 | "一回合里模型到底能做什么、不能做什么。" |
| p06 → p07 | "九个工具里，有几个是有代价的——写操作要先问一句。" |
| p07 → p08 | "把资料放进来之后，怎么才能被问出来。" |
| p08 → p09 | "召回到片段之后，怎么保证引用的每一句都对得上原文。" |
| p09 → p10 | "出题这一步，模型写不出来的时候怎么办。" |
| p10 → p11 | "题和复习排好之后，答案是怎么回到你面前的。" |
| p11 → p12 | "上面这些能力，能量的来源是模型之外的工具。" |
| p12 → p13 | "还有三件用户完全看不见，但撑住了上面所有能力。" |
| p13 → p14 | "以上是能跑的部分。下面是我主动交代的边界。" |

- **光质**：大面积柔光（soft / diffused），**不要硬阴影、不要逆光剪影、不要戏剧性强光**。
- **投影**：浅淡、方向一致、偏软，投影淡度约 20–30%。
- **色温**：统一偏暖（奶白、浅木色），不要冷蓝调、不要黄昏暖橙。

### 3.3 材质与质感规范

- 全部为**哑光**材质：磨砂陶瓷、哑光纸、浅木、磨砂树脂、轻微磨砂金属。
- **不要**：高光镜面、玻璃反射强、镀铬、彩虹渐变、霓虹。
- 微缩 3D 质感（块有厚度、有倒角、有柔影）用于 p05 / p10 / p15；写实静物用于 p01 / p03 / p04 / p06 / p09 / p11 / p13 / p14 / p16。

### 3.4 构图规范

- 主体**居中或居中偏一侧**，另一侧留白给文字。
- 每页主体不超过 3 组物件（p06 的 3×3 九宫格是唯一例外，它本身就是"九个工具"这个论点）。
- 负空间充足，不把画面塞满。
- 焦距统一：**85mm 视角**，浅景深，背景轻微虚化。

### 3.5 文字规范

| 项 | 规范 |
| --- | --- |
| **图上文字** | **标题与副标题直接写进图里**（豆包 / Seedream 4.0 中文渲染准确率约 98%，实测笔画完整、字形端正）。每页提示词已把该页标题原样写入。 |
| **图上数字** | **一律不交给模型**。比例、分数、版本号、日期全部在 PPT 里用文本框叠 —— 数字错一位就是硬伤。 |
| **标题字号** | 30–36pt，粗体，单行不超过 16 字 |
| **副标题** | 16–18pt，灰色 |
| **正文** | 13–15pt，行距 1.5 |
| **表格文字** | 11–12pt |
| **字体** | 思源黑体 / 苹方（`PingFang SC`）；数字与英文可用 `SF Mono` / `Menlo` |
| **对齐** | 全部左对齐（表格除外） |
| **每页字数** | **不超过 120 字**（p15 表格页除外） |

### 3.6 分辨率与文件规范

| 项 | 规范 |
| --- | --- |
| 插图分辨率 | **≥ 1920×1080**，推荐 2K/4K；投屏不虚 |
| 插图格式 | PNG（无损）或高质量 JPG（质量 ≥ 90） |
| PPT 尺寸 | 16:9，33.87×19.05 cm（13.333×7.5 in） |
| 图片嵌入 | 插入后**不要**再缩放到模糊；宁可裁切也要保持原分辨率 |
| 文件位置 | `docs/作品集/参赛/知迹答辩/figures/pXX-中文名.png` |

### 3.7 图片处理规范

- 豆包出图后**不要**直接用：先检查 ① 有没有乱码文字 ② 主体有没有被裁 ③ 有没有不该有的暗角/色偏。
- 需要统一色温时，用 PPT 的"图片格式 → 颜色"统一加一点点**暖色**（饱和度 −5，色温 +5）；**不要**加滤镜模板。
- 需要压字时，在图上叠**纯白半透明矩形**（透明度 15–25%），不要用黑色半透明。

## 五、生成与整合流程（照着做）

1. **建目录**：`docs/作品集/参赛/知迹答辩/figures/`
2. **逐页生图**：从 p01 开始，用本页的中文提示词，每页出 3–4 张候选。
   - 若中文提示词效果不好，换英文版（英文版同样已内嵌中文标题要求）。
   - 若图偏暗/偏冷，追加：`brighten the image, warm up the color temperature, keep shadows very soft`。
   - 若标题出现错字或缺笔画，**优先换一张候选**；都不行才追加
     `the Chinese headline must be rendered with perfectly correct, complete characters`。
   - 若误生出了多余文字，追加：`remove everything except the specified headline, no other text or numbers`。
3. **验收一张图**（四条都过才用）：
   - [ ] **标题文字与本页要求完全一致**（逐字核对，不只看"像不像"）
   - [ ] 标题没有缺笔画、没有错字、没有变形字符
   - [ ] 主体居中、四边不被裁
   - [ ] 整体是浅色调、光从右上来
4. **存盘**：按第四节命名，存进 `figures/`。
5. **排版**：新建 16:9 PPT → 铺底色 `#F7F2E7` → 放图 → 叠正文与数字。
   - **标题已在图上，不必再叠一遍**（避免重影）；正文要点与所有数字用文本框叠。
   - 文本框一律左对齐，页边距统一 **1.2 cm**。
   - 每页底部统一放一条细线（`#C9BFA8`，0.5pt）+ 右下角页码。
6. **通读检查**：
   - [ ] 只读每页标题能连成一条完整论证（论文图 ghost deck 测试）
   - [ ] 每页不超过 120 字
   - [ ] 术语只在技术页出现，背景页不出现技术黑话
   - [ ] **图上没有任何数字**（数字只在 PPT 文本框里，且都能在
     `docs/作品集/参赛/03-评测证据包.md` 找到出处）
   - [ ] 首尾（p01 / p16）的光影与材质一致

## 六、内容口径提醒（**避免自相矛盾**）

- 产品主线只有三句：**整理学习资料 ＋ 自动出错题 ＋ 结合知识库复习**。技术页是支撑，不是主线。
- **不要**把工程内容（权限 / 可恢复 / 门禁 / trace）说成"痛点"或"根本问题"。
- **不要**用"沉淀""错因进脑子""过程没处查"这类说法。
- 数字口径：284 项测试；检索 35 题 / 21 篇语料，Hit@3 = MRR = **0.9714**（词面模式），接真实向量 35/35；意图 15 句，准确率 1.0；消融关掉精排 MRR **0.9571**；上下文压缩 24 条上限 / 保留最近 14 条 / 摘要 ≤ 240 字；掌握度区间 0–100，自评 again −10 / hard −3 / good +5 / easy +10，间隔 0 / 1 天 / 3 天 / 7 天；出题难度分档 <40 基础 / <80 进阶 / ≥80 迁移；embedding 2048 维。

## 七、常见坑

| 坑 | 后果 | 怎么躲 |
| --- | --- | --- |
| 图上的中文出现错字/缺笔画 | 答辩现场直接露怯 | 豆包中文准确率约 98%，但**仍要逐张检查**；发现错字就换一张候选，或把该标题改回 PPT 里叠 |
| 图上的数字写错 | **比乱码更严重** —— 是编造数据 | 提示词里明确写"除标题外不出现其他文字"，**所有数字留在 PPT 里叠** |
| 每页图色调不一致 | 翻页时"不是一套" | 所有提示词共用同一句光线描述，生成后统一加一点暖色调整 |
| 图做成了扁平插画 | 跟参考的写实质感不符 | 提示词里明写 `photorealistic 3D render`，并负面列出 `no flat vector style` |
| 图做成了深色调 | 和 PPT 奶油底打架，也偏"科技宣传" | 明写 `bright high-key`、`light cream backdrop`、`no dark background` |
| 技术页配了人物 | AI 脸崩坏，注意力被带走 | 全篇无人物；p07 最多给一只手 |
| 用生图做表格 | 表格文字与数字容易错 | **表格一律用 PPT 原生表格** |
| 一页塞 200 字 | 投屏读不完 | 每页 ≤ 120 字，其余进讲稿 |
| 首尾页图不像一套 | 收束感打折 | p16 与 p01 用同一套光线/材质词，只换物件 |
