01 背景 · 要做的三件事

整理资料，出题，复习——三件事连起来

三件事不是三个功能，是一条链：每一步的产出，都得成为下一步的输入。

Step 1

整理资料

讲义、课件、笔记、错题照片传进来，按学科分好。

  • PDF / Word / PPT / Excel 原样秒传，用到时才解析建索引
  • PDF 与 PPT 按页切块，引用能落到具体第几页
  • 拍照的板书由多模态模型转成文字，同样可被搜到

Step 2

自动出题

按你传进来的资料出题，不是随便凑一套。

  • 题目依据来自你的资料，不是模型自由发挥
  • 上次做错的方向会多出几道，按错因出变式题
  • 作答后能看参考答案与关键步骤，知道差在哪

Step 3

结合知识库复习

今天该练哪几题，系统排好，不用自己惦记。

  • 按掌握度与到期时间排「今日复习」
  • 薄弱学科与近期误区一并汇总进来
  • 复习时能直接翻回原文那一页，不用重新找
后面几页讲的是支撑这三件事的做法

这一页是全篇的主线，后面所有技术都是为这三件事服务的。

要点在于三件事是一条链：周三能答出"第几页"，靠的是周一已经切好了片段；周日的题能"按错因出"，靠的是这周记下了错因。

02 技术 · 回合编排

一次学习回合，是画出来的一张图

我们没有做成"问一句答一句"，而是把一回合拆成四个节点，每走一步都留一次档。

四个节点

  • route — 先判这轮要干什么：讲解、练习、规划、检索、计算
  • plan — 复杂任务才出计划，简单请求直接进模型，不浪费一轮规划
  • agent — 模型推理，决定这一步该调哪个工具
  • tools — 执行工具、把结果回填，再回到 agent 继续想

节点与分支都写在图上，不藏在某个函数的 if 里。

为什么要画成图

  • 因为它会中断 — 中途关页、下次进来要能从断的地方接着跑
  • 因为它要等人 — 写数据前必须停下来问一句，不能自己决定
  • 因为它会出错 — 哪一步出的问题要能查得到，而不是整段重跑

实现上：每个节点结束都落一次检查点，状态存在库里，进程重启也不丢。

LangGraph 显式状态图 SQLite 检查点 中断 / 恢复 回合 trace 五层归因
这是"断了能接着跑"和"写库前停下来问你"的共同技术前提

技术篇第一项。关键不是用了什么框架，是把一回合显式画出来。

理由三条：它会中断、它要等人、它会出错。这三件事在一次性问答里没法处理。

实现上就是每个节点结束落一次检查点，状态存在库里。

02 技术 · 工具调用

九个工具，模型想调哪个就调哪个

工具是模型唯一能改变外部世界的入口，所以每个工具的契约都写死：名字、参数、例子、边界、错误行为。

查自己的东西

跟"我自己的学习资料"有关的两条路。

  • knowledge_search — 查学科知识库，返回片段带出处
  • mistake_search — 查错题与误区记录，能按关键词过滤并统计同类错误频次

存进去

写入的两个入口，都要过确认。

  • save_note — 把结论沉淀进某个学科库，先弹确认再落库
  • write_file — 写进文件工作区（Markdown / 文本 / 代码），同名会覆盖

看工作区

让模型能看见用户自己放的文件。

  • read_file — 读取工作区里的一个文本文件
  • list_files — 列出全部文件，按最近修改排序

问外面

资料之外的部分，才走这条路。

  • web_search — 联网搜索（下一页细讲）
  • fetch_url — 读取网页正文，自动去标签与脚本
  • calculator — 计算数学表达式

工具失败不炸回合。单次超时 + 只对可重试错误做有限退避重试；还失败就转成一条普通工具消息告诉模型"这条路不通"，让它换条路走——整轮不会因此崩掉。

工具数量与分工在代码里集中注册，模型的可用范围由下一页的权限决定

这一页讲"模型能干什么"。九个工具分四类：查自己的、存进去、看工作区、问外面。

强调两点。第一，每个工具的契约都写死：名字、参数、例子、边界、错误行为——工具描述写不清楚，模型就会用错。第二，工具失败不炸回合：超时加有限重试，还失败就变成一条消息告诉模型换条路。

（提示）下一页讲权限，是这一页的延续。

02 技术 · 工具权限

看得见的工具，不等于跑得动的工具

这是"AI 不会擅自改你的数据"这句话的技术兑现——它落在执行层，不落在提示词里。

第一层：模型看得见哪些

  • 讲解 · 检索 — 全部工具都能用
  • 练习 — 只给只读工具，练习时不允许写你的库
  • 进度 — 不给任何工具

按角色裁剪工具清单，不是靠提示词说"你不能用这个"。

第二层：执行时放不放行

  • 讲解 · 检索 — 放行；写操作仍要经过人确认
  • 练习 — 写操作直接拒绝，返回拒绝理由
  • 进度 — 一律拦截

即使模型想办法绕过清单，执行层也会挡下来。

为什么两层都要有。只做第一层，模型仍会说出被禁工具的名字然后调用失败；只做第二层，模型会一遍遍重试、白白烧轮次。两层一起做，"看得见"和"跑得动"才都对得上。

还有一处：练习角色被拒写时，有回归测试断言"数据确实没被改"

这一页是我们产品承诺的技术兑现：AI 不会擅自改你的数据。

两层：第一层决定模型看得见哪些工具，第二层决定执行时放不放行。两层都必要——只做第一层，模型仍会说出被禁工具名然后失败；只做第二层，模型会反复重试。

还有一个细节：写操作即使放行，也要经过人确认——这就是下一页"停下来问一句"的来源。

02 技术 · 检索

中文资料难找，所以不只找一路

四路不是堆料，每一路都对应一类实测出来的漏召回。

按字面找

trigram 分词，中文按字面也能命中，不需要先分词。

局限：错一个字就漏

换个说法找

走同义词表：本征值 → 特征值，queue → 队列，中英对照也在表里。

局限：靠词典，推断有噪声

短词兜底

「秩」「队列」这种两个字，进不了 trigram 索引，单独走一路。

局限：按覆盖度排序，精度中等

按意思找

字面全不同、意思相近仍能召回，走向量相似度。

局限：没有真实模型时不可靠

技术上有个关键点：这四路的分数单位不一样，不能直接相加，所以按名次加权融合（k=60）；融合完再补一层词面精排，看谁的原文里真的出现了你问的字、且出现在标题上。

消融证据：关掉精排，MRR 从 0.9714 掉到 0.9571，命中数不变——它改善的是排序，不是召回。35 道题里有 1 道是同义词题，接上真实向量模型后 35 道全对。

引用能落到「第 N 页」，是这一层和下一层的共同产出

这一页讲检索。四路各对应一类真实漏掉的查询：错字、同义词、两个字的专业词、换个说法问。

技术重点是：四路分数单位不一样，不能直接相加，所以按名次加权融合，再补一层词面精排。

证据是消融：关掉精排 MRR 从 0.9714 掉到 0.9571——它改善排序，不是召回。接真模型后 35 题全对。

02 技术 · MCP

接外部工具，用的是现成的标准

MCP（Model Context Protocol）是连接 AI 应用与外部工具、数据源的一套开放标准，官方拿它类比 LSP。

我们做了什么

  • 自己写了一个最小客户端 — stdio 上的 JSON-RPC，能启动外部 server、列出工具、调用工具、关闭
  • 零外部依赖 — 不用装任何第三方 MCP 库，一个文件就能跑；缺的功能也不影响主流程
  • 桥接进工具表 — 外部 server 的工具被发现后，转成模型能调用的工具直接注册进去

换来什么 / 代价

  • 工具能即插即用 — 外部能力不用改我们的代码就能接进来
  • 跨宿主可复用 — 别的 AI 应用也能用同一批 server
  • 代价是只覆盖常用方法 — 完整规范还有采样、任务等扩展，我们没做，也暂时用不上

为什么用现成标准，而不是自研协议：自研协议没有生态，换个宿主就废掉了；MCP 已经是事实标准，接一次到处能用。我们的取舍是：只做我们用得上的部分，别的明确说"没做"。

外部工具接入不影响主流程：MCP 不可用时，系统照常工作

这一页讲 MCP。先说它是什么：连接 AI 应用和外部工具的一套标准，官方拿它比作 LSP——以前每个编辑器都要自己实现每种语言的服务，接了 LSP 之后一次接入到处可用。

我们的做法是自己写最小客户端：好处零依赖、可控；代价是只覆盖常用方法，完整的规范里还有采样、任务这些扩展我们没做。

为什么不用现成库也不用自研：自研没有生态，换宿主就废；MCP 是事实标准，接一次到处能用。

02 技术 · 联网搜索

资料里没有的，才去外面找

这是唯一一个会引入外部信息的能力，所以对它的约束也最严。

怎么用

  • 一次给几个不同角度的问题 — 不是只搜一次，而是拆成 2–4 个角度各搜一遍，再把结果合起来。单一角度的搜索很容易被同一个来源占满
  • 结果自动清洗 — 网页正文去掉标签和脚本，只留能读的文本
  • 配套读页工具 — 搜到结果后可以再抓正文，不只看摘要

接了哪些源

  • DuckDuckGo · Tavily — 通用搜索，海外内容多
  • 必应中国 · 博查 — 中文内容更全
  • DeepSeek 内置搜索 — 接的是 DeepSeek 时自动启用，不用另配 key

按配置自动选择，不需要用户逐个配。

一条硬约束：搜回来的内容一律标为「外部资料」，和用户自己传的资料分开——不然模型分不清哪句是"我说的"、哪句是"网上说的"，出错时也说不清责任。

能力按需触发：用户资料里有答案时，不走联网这条路

这一页讲联网搜索。定位很清楚：用户自己的资料里没有的，才去外面找。

做法上值得说：不是只搜一次，而是把问题拆成两到四个角度各搜一遍，再把结果合起来——单一角度很容易被同一个来源占满。

最重要的约束在页面底部：搜回来的内容一律标成外部资料，不和用户自己传的资料混在一起，不然模型分不清哪句是谁说的。
