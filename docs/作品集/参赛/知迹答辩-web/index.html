01 背景 · 实际是这样用的

一周里发生的事

这条链上任何一步断了，后面的都接不上。资料没切好，提问就定位不到页；错因没记下，出题就无从针对；掌握度没更新，复习就排不准。接下来九页技术，讲的就是怎么保证它不断。

02 技术 ① 回合编排

一次学习回合，是画出来的一张图

实现上两个坑，我们都踩过：① 检查点与聊天消息是两套存储——只删会话会留下孤儿线程（实测出现过 33 个线程对 7 个会话），所以删除必须级联清理；② 中断时模型已经说过半句话，恢复后要把中断前后的消息合并落库，否则界面上会出现重复的半句。

技术篇第一项。关键不是用了什么框架，是把一回合显式画出来。

图上四个绿点是检查点——每个节点结束都存一次，进程重启也不丢。

最值得讲底部那个坑：检查点和消息是两套存储，只删会话会留孤儿线程，我们实测到过 33 对 7，所以做了级联清理。这是"做过"和"看过教程"的区别。

02 技术 ② 工具调用与治理

九个工具，模型想调哪个就调哪个

契约写死 —— 名字、参数、例子、边界、错误行为都写清；工具描述含糊，模型就会用错。

同轮并发 —— 一轮里多个工具不等前一个跑完，并行发出。

失败不炸回合 —— 超时 + 只对可重试错误退避；仍失败就转成一条工具消息，让模型换条路。

这一页讲模型能干什么，以及怎么管住它。左边是九个工具连着 agent 的关系图。

右边三条是治理规则，其中并发和失败转消息最容易被忽略。

（提示）MCP 接进来的外部工具也在这张表里，模型看不出区别。

02 技术 ③ 工具权限

看得见的工具，不等于跑得动的工具

为什么两层都要有。只做第一层，模型仍会说出被禁工具的名字然后调用失败；只做第二层，模型会一遍遍重试、白白烧轮次。两层一起做，"看得见"和"跑得动"才都对得上。这层不在提示词里，所以能被回归测试直接断言：练习角色调用写工具被拒后，数据确实没被改。

这一页是我们产品承诺的技术兑现。图上从左到右是四道关：模型 → 看得见哪些 → 放不放行 → 执行。

底下那个红叉是"被拒的写操作"——不是提示词约束的，所以能被回归测试直接断言"数据没被改"。

02 技术 ④ 检索与选库

中文资料难找，所以不只找一路

这一页讲检索，两个机制。四路召回解决"找得到"，选库解决"在哪个库找"。

最值得说的是中间那条：四路的分数单位不同，不能直接相加，所以按名次加权——这是混合检索里最容易做错的地方。

证据在底下：关掉精排 MRR 从 0.9714 掉到 0.9571，接真模型后 35 题全对。

02 技术 ⑤ 资料入库

资料进来这一步，脏数据进不来

还有三件事：① pypdf 抽出来的是平铺文本，我们把它重排成结构化 Markdown；② 板书照片走视觉转写成笔记再入库；③ 对话里的结论可以智能沉淀成独立笔记（按笔记规范去掉对话腔，模型提炼失败就回退原文转存，绝不丢内容）。原件始终保留，引用点开就是真的那一页。

这一页讲资料进来这一步。图上那条红线是重点：格式对不上直接拒收——不让解析失败的垃圾混进索引，否则后面所有检索质量都被它拖垮。

还有"原件始终保留"：所以能内联预览、能下载原文，引用点开就是真的那一页。

02 技术 ⑥ 自动出题与详解

宁可给一道模板题，也不给半道 AI 题

差别就在这一条：出题失败可以降级，详解失败不能降级。所以详解的策略是：要么给出经过学科事实检验的答案，要么明确告诉用户"这题暂无详解"。

这一页讲出题。核心观点一句话：宁可给一道模板题，也不给半道 AI 题。

图上右上是唯一的红框：详解没有退路，因为答案对错由学科事实决定，编一个参考答案比不给更糟。

工程细节：详解懒生成 + 落库缓存，第一次 3.7 秒，之后 0.02 秒。

02 技术 ⑦ 复习调度与掌握度

打一个分，决定你明天练不练它

规则是纯函数 —— 给定「自评等级 + 当前掌握度」，算出「新掌握度 + 下次间隔」，不碰数据库也不碰 HTTP，所以能被一行断言测清。

围着它长出来的东西 —— 今日复习（到期题 + 薄弱学科 + 近期误区）、学习周报、活跃度热力图。

非法评分直接抛异常 —— 不会算出荒谬的复习时间。

这一页讲复习是怎么排的。左边是四档自评围着掌握度的图，数值都标在图上。

最想传达的是右上那句：这套规则是纯函数，不碰数据库、不碰 HTTP，所以能被一行断言测清楚——越关键的逻辑越要能脱离环境验证。

02 技术 ⑧ 外部能力

接外面的世界，用现成的标准

MCP · 自写最小客户端 —— stdio 上的 JSON-RPC，能启动外部 server、列工具、调工具、关闭；零第三方依赖，缺的功能也不影响主流程。

代价我们说清楚 —— 完整规范的采样、任务等扩展我们没做，也暂时用不上。选标准而不自研，是因为自研协议没有生态、换个宿主就废。

这一页讲两件会引入外部内容的能力。左边图：左边是 MCP servers，右边是搜索源，中间是知迹。

两条硬约束：MCP 不可用时系统照常工作；搜回来的内容一律标成外部资料，不和用户自己的资料混。

02 技术 ⑨ 上下文、预算与护栏

看不见的三件事，撑住上面所有能力

上下文压缩

拆散工具调用对，模型会看到孤立结果而报错——所以裁剪只能从轮次边界下刀。

模型路由与预算

该省的地方省，不在关键处省；超预算是拦下来，不是提醒。

护栏

自己写的规则，纯函数、可单测——不靠模型自觉。

还有一件贯穿全局的：可观测。每个回合都留 trace，一次会话能被读成一棵诊断树——第几步、调了什么工具、在哪出错，一眼看到，不用猜。

这一页讲三件用户看不见、但撑住整套系统的事。

三张图各配一个数：24/14 的裁剪、预算环、护栏波形。

最值得说的是压缩那条：只能从整轮边界裁，否则会把"工具调用—结果"拆散，模型看到孤立结果会报错。

03 应用与验证

它跑起来是什么样，怎么证明没坏

知识库页实拍：左学科目录树 · 中资料列表 · 右可直接就着当前库提问

284 项自动测试 —— 全部离线、零 API 消耗，改一次跑一遍。

两份固定考卷 —— 检索 35 题、意图 15 句，各有基线；掉出容差 0.05 命令返回非零，可接进提交前检查。

消融开关 —— 关掉精排 MRR 从 0.9714 掉到 0.9571，机制有没有用当场可见。

CRUD 硬规则 —— 删除一律级联，约束冲突翻译成 4xx，归属校验状态码一致。

真实界面，不是设计稿。三个动作在界面上是连着的：传资料在知识库页、出题在练习页、复习安排在今日复习和日程页。

右边四条是"怎么证明没坏"。特别强调离线：因为离线，所以每次改动都能立刻复跑。

04 边界与下一步

六项能力：两项达标，三项一半，一项没做

能力项状态依据 / 还缺什么

长上下文管理一半有抽取式摘要与预算控制；缺关键事实外置成结构化笔记
长期记忆一半按课程隔离、写入前确认；缺过期、替换与删除机制
任务级成功率评测没做现有考卷只测「找到没」「分类对不对」，不测「这次复习有没有用」
下一步 1 · 任务级成功率评测 下一步 2 · 记忆的过期与删除 下一步 3 · 更难的检索考卷 三项都不需要换架构，都能在现有门禁里验证

主动交代边界，我们希望它看起来体面。

完全没做的是任务级评测——考卷只测"找到没""分类对不对"，不测"这次复习到底有没有用"。这是最该补的一项。

三项都能在现有门禁里验证，不需要换架构。
