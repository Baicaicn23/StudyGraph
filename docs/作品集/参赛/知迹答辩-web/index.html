01 背景 · 要做的三件事

整理资料，出题，复习——三件事连起来

三件事不是三个功能，是一条链：每一步的产出，都得成为下一步的输入。

Step 1

整理资料

讲义、课件、笔记、错题照片传进来，按学科分好。

  • PDF / Word / PPT / Excel 原样秒传，用到时才解析
  • PDF 与 PPT 按页切块，引用能落到具体第几页
  • 拍照的板书由多模态模型转成文字，同样可被搜到

Step 2

自动出题

按你传进来的资料出题，不是随便凑一套。

  • 题目依据来自你的资料，不是模型自由发挥
  • 上次做错的方向会多出几道，按错因出变式题
  • 作答后能看参考答案与关键步骤

Step 3

结合知识库复习

今天该练哪几题，系统排好，不用自己惦记。

  • 按掌握度与到期时间排「今日复习」
  • 薄弱学科与近期误区一并汇总进来
  • 复习时能直接翻回原文那一页
后面九页技术，都是围绕这三件事

这一页是全篇主线，后面所有技术都为它服务。

要点是三件事是一条链：周三能答出"第几页"，靠周一已切好片段；周日能"按错因出题"，靠这周记下错因。

02 技术 ① 回合编排

一次学习回合，是画出来的一张图

不是"问一句答一句"——四个节点，每走一步都留一次档。

四个节点

  • route — 判这轮要干什么：讲解 / 练习 / 规划 / 检索 / 计算
  • plan — 复杂任务才出计划，简单请求直接进模型，不浪费一轮
  • agent — 模型推理，决定这一步调哪个工具
  • tools — 执行、回填，再回到 agent 继续想

三个"必须"

  • 会中断 — 中途关页，下次进来从断的地方接着跑
  • 要等人 — 写数据前停下来问一句，不能自己决定
  • 会出错 — 哪一步出的问题要能查得到，而不是整段重跑

实现上两个容易踩的坑，我们都踩过：① 检查点与聊天消息是两套存储——只删会话会留下孤儿线程（实测出现过 33 个线程对 7 个会话），所以删除必须级联清理；② 中断时模型已经说过半句话，恢复后要把中断前后的消息合并落库，否则界面上会出现重复的半句。

技术栈：LangGraph 状态图 + SQLite 检查点（AsyncSqliteSaver）

技术篇第一项。关键不是用了什么框架，是把一回合显式画出来，因为它一定会中断、一定要等人、一定会出错。

这一页最值得讲的是底部那个坑：检查点和消息是两套存储，只删会话会留孤儿线程，我们实测到过 33 对 7，所以做了级联清理。这是"做过"和"看过教程"的区别。

02 技术 ② 工具调用与治理

九个工具，模型想调哪个就调哪个

工具是模型唯一能改变外部世界的入口，所以治理比功能本身更花功夫。

查自己的东西

  • knowledge_search — 查学科知识库，返回片段带出处
  • mistake_search — 查错题与误区，能按关键词过滤并统计同类错误频次

存进去

  • save_note — 沉淀进某个学科库，先弹确认再落库
  • write_file — 写进文件工作区，同名会覆盖（工具说明里写明）

看工作区

  • read_file — 读一个文本文件
  • list_files — 列出全部文件，按最近修改排序

问外面

  • web_search · fetch_url · calculator
  • 资料之外的部分才走这条路（见第 12 页）

四条治理规则：① 契约写死——名字、参数、例子、边界、错误行为，工具描述写不清楚模型就会用错；② 同轮多个工具并发执行，不等前一个跑完；③ 单次超时 + 只对可重试错误做有限退避，参数写错这种不该重试；④ 失败转成一条工具消息告诉模型"这条路不通"，让它换条路走，整轮不崩。

MCP 接进来的外部工具与本地工具走同一张表，模型看不出区别

这一页讲模型能干什么，以及怎么管住它。

九个工具分四类。重点是底部那四条规则，其中两条最容易被忽略：并发和失败转消息。

工具描述质量直接决定模型用得对不对——官方也强调这点：我们自己的工具如果写含糊了，模型就会调错。

02 技术 ③ 工具权限

看得见的工具，不等于跑得动的工具

这是"AI 不会擅自改你的数据"这句话的技术兑现——它落在执行层，不落在提示词里。

第一层：模型看得见哪些

  • 讲解 · 检索 — 全部工具都能用
  • 练习 — 只给只读工具，练习时不允许写你的库
  • 进度 — 不给任何工具

第二层：执行时放不放行

  • 讲解 · 检索 — 放行；写操作仍要经过人确认
  • 练习 — 写操作直接拒绝，并返回拒绝理由
  • 进度 — 一律拦截

为什么两层都要有。只做第一层，模型仍会说出被禁工具的名字然后调用失败；只做第二层，模型会一遍遍重试、白白烧轮次。两层一起做，"看得见"和"跑得动"才都对得上。

这层不在提示词里，所以能被回归测试直接断言：练习角色调用写工具被拒后，数据确实没被改。

权限判定表与工具注册表分开，改角色不用改工具

这一页是我们产品承诺的技术兑现。

两层缺一不可，这个判断有具体依据：只做第一层模型仍会说出被禁工具名然后失败；只做第二层模型会反复重试。

最关键的一句在底部：这层不在提示词里，所以能被回归测试直接断言——我们测了"被拒之后数据没被改"。

02 技术 ④ 检索与选库

中文资料难找，所以不只找一路

四路召回解决"找得到"，选库解决"在哪个库找"。

四条召回

  • 按字面 — trigram 分词，中文不必先分词（错一个字就漏）
  • 换说法 — 同义词表：本征值 → 特征值、queue → 队列（靠词典，有噪声）
  • 短词兜底 — 「秩」「队列」两个字进不了 trigram 索引，单独一路
  • 按意思 — 字面全不同、意思相近仍能召回（没真模型时不可靠）

选库：先决定搜哪个库

  • 小模型从候选库里挑 1–3 个相关的
  • 模型编造的库名一律过滤，只保留候选内的
  • 判断不出就回落全库——绝不因为选库失败而拒答
  • 也可以手动锁定知识库，绕过这一步

两个技术点。① 四路的分数单位不同，不能直接相加，所以按名次加权融合（k=60），融合完再补一层词面精排；② 选库用小模型而不是大模型，省成本，而且它的失败被设计成"降级"而不是"报错"。

消融证据：关掉精排，MRR 从 0.9714 掉到 0.9571（命中数不变）；接上真实向量模型后 35 道题全对。

证据：35 题考卷 / 21 篇语料，检索 Hit@3 与 MRR 都有基线

这一页讲检索，两个机制。

第一个是四路召回，解决"中文资料难找"；第二个是选库，先决定在哪个库搜，用小模型挑，挑不出来就回落全库。

最值得说的是"四路分数单位不同不能相加"这个坑——混合检索里最容易做错的地方。

证据是消融：关掉精排 MRR 从 0.9714 掉到 0.9571，接真模型后 35 题全对。

02 技术 ⑤ 资料入库

资料进来这一步，脏数据进不来

入库不是"把文件转成文本"，而是一条有校验、有兜底、有保留原件的流水线。

秒传 + 懒解析

  • 上传原样落盘，不解析、不建索引
  • 真正被用到时才解析建索引
  • 省时间，也省掉一批必然失败的解析

魔数校验：拒收脏文件

  • docx / pptx / xlsx 是 PK 容器，老 xls 是 OLE2
  • 扩展名说的和实际格式对不上 → 直接拒收
  • 不让解析失败的垃圾混进检索索引

三种切块方式

  • PDF / PPT 按页切，引用精确到页
  • Markdown 按标题切，标题和内容不分离
  • 纯文本盲切兜底

另外三件事：① pypdf 抽出来的是平铺文本，我们把它重排成结构化 Markdown；② 板书照片走视觉转写成笔记再入库；③ 对话里的结论可以智能沉淀成独立笔记（按笔记规范去掉对话腔，模型提炼失败就回退原文转存，绝不丢内容）。原件始终保留，页面里能内联预览、能下载原文。

演示素材覆盖 PDF / Word / PPT / 图片四类，解析后片段全部带出处

这一页讲资料进来这一步。三块：怎么不浪费时间、怎么不脏、怎么切。

最值得讲的是魔数校验：扩展名说是 docx、实际不是，就直接拒收——不让解析失败的垃圾混进索引，否则后面所有检索质量都被它拖垮。

还有一个细节：原件始终保留，所以能内联预览、能下载原文，引用点开就是真的那一页。

02 技术 ⑥ 自动出题与详解

宁可给一道模板题，也不给半道 AI 题

出题这条链路最容易崩在模型上，所以每一处都写了"失败怎么办"。

出题

  • 依据来自用户资料，并带上错因上下文
  • 难度按掌握度分档，写进提示词（难度决定考察方式，不只是措辞）
  • 模型写题失败、返回解析不了 → 退回模板，绝不抛异常，调用方不用处理

详解（唯一没有退路的环节）

  • 答案对错由学科事实决定，没有模板可退
  • 所以不达标就不给，也不拿模型的话凑
  • 懒生成 + 落库缓存：第一次算约 3.7 秒，之后直接读缓存约 0.02 秒

差别就在这一条：出题失败可以降级，详解失败不能降级——因为编一个"参考答案"比不给答案更糟。所以详解的策略是：要么给出经过学科事实检验的答案，要么明确告诉用户"这题暂无详解"。

出题失败率不影响可用性；详解按需生成，同一题不重复计算

这一页讲出题。核心观点一句话：宁可给一道模板题，也不给半道 AI 题。

出题失败可以退回模板、绝不抛异常；详解是唯一没有退路的环节，因为答案对错由学科事实决定，编一个参考答案比不给更糟。

还有工程细节：详解懒生成 + 落库缓存，第一次 3.7 秒，之后 0.02 秒。

02 技术 ⑦ 复习调度与掌握度

打一个分，决定你明天练不练它

复习不是"每天推几题"，而是一套掌握度 + 到期时间的规则。

四档自评 → 掌握度 + 下次间隔

  • again — 掌握度 −10，立刻再来
  • hard — 掌握度 −3，1 天后
  • good — 掌握度 +5，3 天后
  • easy — 掌握度 +10，7 天后
  • 掌握度夹在 0–100 之间，越低越早出现

围绕它长出来的东西

  • 今日复习 — 到期题 + 薄弱学科 + 近期误区
  • 学习周报 — 这周的练习量、掌握度升降、新增错题
  • 活跃度热力图 — 哪些天真的在学

为什么值得单独讲：这套规则是纯函数——给定"自评等级 + 当前掌握度"，算出"新掌握度 + 下次间隔"，不碰数据库也不碰 HTTP。所以它能被一行断言测清楚：review("good", 60) 必然等于掌握度 65、三天后到期。越关键的逻辑，越要能脱离环境被验证。

非法评分直接抛领域异常，不会算出荒谬的复习时间

这一页讲复习是怎么排的。四档自评对应掌握度增减和下次间隔，都写在页上了。

最想传达的是底部那句：这套规则是纯函数，不碰数据库、不碰 HTTP，所以能被一行断言测清楚——越关键的逻辑越要能脱离环境验证。

02 技术 ⑧ 外部能力

接外面的世界，用现成的标准

两件会引入"别人的东西"的能力，所以约束都写在最前面。

MCP · 接外部工具

  • 自写最小 stdio JSON-RPC 客户端：启动 / 列工具 / 调用 / 关闭
  • 零第三方依赖，一个文件就能跑；缺的功能也不影响主流程
  • 外部工具被发现后桥接成模型能调的工具，注册进同一张表
  • 代价：完整规范的采样、任务等扩展我们没做

联网搜索 · 问外面

  • 一次给 2–4 个不同角度的问题，多路召回再合并——单一角度容易被同一个来源占满
  • 结果自动清洗：去标签与脚本，只留正文
  • 源：DuckDuckGo / Tavily / 必应中国 / 博查 / DeepSeek 内置（接 DeepSeek 自动启用）

一条硬约束：搜回来的内容一律标为「外部资料」，与用户自己传的资料分开——不然模型分不清哪句是"我说的"、哪句是"网上说的"，出错时也说不清责任。同理，用户资料里有答案时就不走联网这条路。

MCP 不可用时系统照常工作；联网搜索默认不参与答题路径

这一页讲两件会引入外部内容的能力。MCP 与联网搜索。

MCP 我们的取舍很明确：自写最小客户端换零依赖，代价是只覆盖常用方法，扩展明确说没做。

联网搜索最值得说的是多角度召回，以及那条硬约束：外部资料必须标出来，不能和用户自己的资料混。

02 技术 ⑨ 上下文、预算与护栏

看不见的三件事，撑住上面所有能力

这三样不出现在界面上，但少一样整套系统就会失控。

上下文压缩

  • 超过 24 条就压，只从整轮边界裁
  • 不拆散"工具调用—结果"这对消息
  • 抽取式摘要，上限 240 字，不用模型

模型路由与预算

  • 按意图与复杂度选模型档位
  • 每次调用记 token，当日超预算直接阻止
  • 该省的地方省，不在关键处省

护栏

  • 输入拦越界与提示词注入
  • 输出拦空回答与系统提示词泄漏
  • 自己写的规则，纯函数、可单测

还有一件贯穿全局的：可观测。每个回合都留 trace，一次会话能被读成一棵诊断树——第几步、调了什么工具、在哪出错，一眼看到，不用猜。

这三样 + trace 都是纯函数或可重放的，所以能离线测

这一页讲三件用户看不见、但撑住整套系统的事：上下文压缩、模型路由与预算、护栏。

最值得说的是压缩那条：只能从整轮边界裁，否则会把"工具调用—结果"拆散，模型看到孤立的工具结果会报错。

另外 trace 那句可以顺带提：一次会话能读成诊断树，出问题不用猜。
