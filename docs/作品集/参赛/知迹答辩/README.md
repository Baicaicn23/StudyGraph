# 知迹答辩 PPT · 交付说明

> **这套 PPT 是什么**：16 页答辩演示文稿，学术风（蓝白、证据驱动），
> 面向**高校竞赛答辩**场景。内容围绕「Agent 从 demo 走向生产的工程化落地」，
> 每一页的结论都对应可验证的代码与数据。

项目量级（10036 行后端 / 50 端点 / 284 测试）也自然被看见。详见 `STORY.md` §〇、§四。

## 三、要做的三件事

### ① 生成三张配图

按 `assets/配图提示词.md` 里的提示词生成，**同名覆盖** `assets/` 下对应文件：

| 文件 | 用于 | 尺寸建议 |
| --- | --- | --- |
| `p01-cover-desk.png` | 封面 | 1240×1440（竖构图，右半幅） |
| `p07-gate.png` | p07 写入确认 | 1600×900（横构图，中央大图） |
| `p16-closing-desk.png` | p16 收束 | 1040×1440（竖构图，右半幅） |

**三张必须是同一套光线与材质**（右上方 45° 柔光、哑光、浅色调、3D 写实），
否则翻页时能看出不是一套。p16 与 p01 要像同一个场景的两个时刻。

生图后**不需要改 PPT** —— 图片路径是固定的，覆盖即生效。

### ② 如需改文案

改 `STORY.md` 里的口径表 → 改 `scripts/build_slides.py` → 重跑：

```bash
uv run python scripts/build_slides.py
P="docs/作品集/参赛/知迹答辩"
for i in 03 04 05 06 07 08 09 10 11 12 13 14 15 16; do
  slidep upsert-dsl "$P/知迹答辩.pptx" --dsl-file "$P/slides/$i.slide" --page-index $((10#$i - 1))
done
```

> ⚠️ **p01 / p02 是手写文件**（不在脚本里），要改就直接编辑 `slides/01.slide` / `02.slide`。

### ③ 校验

```bash
P="docs/作品集/参赛/知迹答辩"
officecli validate "$P/知迹答辩.pptx"                    # 期望：no errors found
officecli view "$P/知迹答辩.pptx" screenshot --grid 4 -o /tmp/deck.png   # 一张图看完 16 页
```

## 五、口径提醒（讲的时候最容易说错的）

| 项 | 数字 |
| --- | --- |
| 检索评测 | 35 题 / 21 篇语料，Hit@3 = MRR = **0.9714** |
| 真实向量 | **35 / 35** 全中 |
| 消融（关掉词面精排） | MRR **0.9714 → 0.9571** |
| 意图分类 | 15 句，准确率 **1.0** |
| 自动测试 | **284 passed**（全 Mock，零 API 消耗） |
| 工程规模 | 后端 10036 行 / 前端 10325 行 / 50 端点 |
| 检索权重 | 1.0 / 0.5 / 0.8 / 1.0，RRF k=60 |
| 上下文 | 24 条上限 / 保留 14 / 摘要 ≤240 字 |
| 工具轮次 | 最多 **6** 轮 |
| 掌握度 | 0–100；−10 / −3 / +5 / +10；0 / 1 / 3 / 7 天 |

Reranker 重排、反思式自我批判。**不得以已完成口径出现。**
