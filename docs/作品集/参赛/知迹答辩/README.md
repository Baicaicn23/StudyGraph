### 叙事为什么这么排

**先情景，再问题，最后实现。** 开场不讲架构不讲评测，先讲一个"翻车"的经历 ——
评委先被打动，才愿意听完后面的技术。

p02 讲的是**小李的一周**（周一晚上 / 周三下午 / 周五晚上，第一人称「我」，
带 [P12]、「概念混淆」这类具体细节），右栏才从这段经历里抽出「那几次翻车，坏在三处」。
p04 讲的是**换成知迹之后**的同一周 —— 两页是「翻车 → 后来」，不重复。

而每一页的标题**都是结论句**（不是主题词），只读标题就能读完整条论证：
「资料存了一百份…」→「凭什么它就比前两个准」→「只死磕三件事」→「每一步都留得下痕迹」
→「每一句都能点回原页」→「必须等你点头」→「每一层都能单独测」→「说清楚比多做一点更有用」。

### 技术段是**递进的**，不是并列的

p05 与 p06 不是"两个亮点"，是**一条链**：

```
p06 答得准   四路召回 + 逐页切块 + 引用跳转  →  找到了、说得清了
             结论条收尾：「…但模型接下来要动手，这还只是回答问题。」
p07 管得住   状态图 + schema/执行层/人在环    →  动手时权限由系统说了算
             结论条收尾：「答得准 + 管得住 = 敢信」
p08 证据     →  敢信之后要证明：它今天没比昨天变笨
```

**讲的时候一定要把 p06 结尾那句念出来** —— 它是整条技术链的接缝。

### 技术怎么讲成人话

| 别这么写 | 这么写 |
| --- | --- |
| 四路召回 + 加权 RRF 融合 | 「四路同时去找，答案里的每一句都能点回原页」 |
| 工具最小权限双层校验 | 「模型能说什么由它定，能做什么由系统定」 |
| 上下文压缩与 token 预算 | 「用户看不见的三件事，撑住上面所有能力」 |
| 8 个可评测能力项 | 「六项能力：两项达标，三项一半，一项没做」 |

## 三、插图分工（**最重要的一条**）

| 类型 | 怎么来 | 说明 |
| --- | --- | --- |
| **机制图 / 流程图** | **PPT 原生形状画** | 状态图、权限分层、检索管线、切块示意、调度环 —— **生图模型画不准部件关系、顺序、数量**，这类图必须用形状画 |
| **真实界面截图** | 直接用 `assets/ui-*.png` | 知识库页、练习页，是**真实运行界面的证据**，不要生图替代、不要加滤镜 |
| **氛围图** | **交给豆包生图** | 只有 p01 封面、p16 收束两张 |
| **表格** | PPT 原生表格 | 不用生图做表格 |

**要生的图只有 2 张**，提示词在 [`assets/配图提示词.md`](assets/配图提示词.md)（中英双版 + 通用规格 + 验收清单）。

> 但请记住：**那些图适合当氛围示意，不适合当机制图**（结构与数字会错）。

## 五、边界与诚实（**这是加分项，不是减分项**）

p08 讲六项能力，p10 还预埋了三个高频追问的备答。**主动说局限比硬杠加分得多。**

三个必答的追问与要点：

| 追问 | 回答要点 |
| --- | --- |
| 「我直接用 ChatGPT 不行吗？」 | ChatGPT 是一问一答，没有状态也不管你明天记不记得；知迹把错题和知识库变成上下文，用 LangGraph 跑流程。**更关键的是它可能编造页码，而知迹每个出处都能精确跳回你上传的第 18 页** |
| 「你连登录都没有，是不是没做完？」 | 承认这是当前最大短板；精力全放在最难的「Agent 核心链路 + 防幻觉检索」上，目前是单机自用产品；体检报告已列为 P0，数据库的 user_id 隔离已做好，接多租户是接口层工作 |
| 「这个项目有什么了不起的？」 | 不比 Demo 功能多，但**每个结论都能被复现**：284 项测试全绿、35 题考卷 0.9714、关掉精排立刻掉到 0.9571。敢把没做的部分摆出来 —— 体检报告和这份 PPT 一样重要 |
