> **这套 PPT 是什么**：16 页答辩演示文稿，学术风（蓝白、证据驱动），

### 讲法的三条设计原则

1. **先让人代入，再讲工程**。p02 是"一个学生的一周"——纯情景，不谈技术；
   p03 才点出真问题（做错了你不知道）；p04 才抽象成三道坎。**顺序反了读者就跟不上**。
2. **每页左侧是真实代码**（带 `文件:行号`），右侧是把这段代码画成的示意图。
   读者能自己验证，不是听讲。p05–p12 八页统一这个版式，是全篇最硬的部分。
3. **七关是问题链，不是模块清单**。看得懂意图 → 看得准资料 → 管得住工具 → 说得清出处
   → 练得下去 → 记得住 → 省得下来。**每一关都是上一关逼出来的**。

`STORY.md` §1.3 给了**页间过渡句**——讲的时候念出来，PPT 上不写。这是防"跳跃感"的关键。

## 三、要做的三件事

### ① 生成两张配图

按 `assets/配图提示词.md` 生成，**同名覆盖** `assets/` 下对应文件：

| 文件 | 用于 | 尺寸 |
| --- | --- | --- |
| `p01-cover-desk.png` | 封面右半幅 | 1240×1440（竖构图） |
| `p16-closing-desk.png` | 收束页右半幅 | 1040×1440（竖构图） |

**两张必须是同一个场景**（同桌子、同光线、同材质）——把 p01 的成品当参考图上传给豆包。
**生成后不需要改 PPT**，覆盖即生效。

### ② 如需改文案

改 `STORY.md` 的口径表 → 改 `scripts/build_slides.py` → 重跑：

```bash
uv run python scripts/build_slides.py
P="docs/作品集/参赛/知迹答辩"
for i in 02 03 04 05 06 07 08 09 10 11 12 13 14 15 16; do
  slidep upsert-dsl "$P/知迹答辩.pptx" --dsl-file "$P/slides/$i.slide" --page-index $((10#$i - 1))
done
```

> ⚠️ **p01 是手写文件**（不在脚本里），要改直接编辑 `slides/01.slide`。
> ⚠️ **重跑后要重新写页名**（`slide_titles.json` → `officecli open` / 多次 `set` / `close`）。

### ③ 校验

```bash
P="docs/作品集/参赛/知迹答辩"
officecli validate "$P/知迹答辩.pptx"                              # 期望：no errors found
officecli view "$P/知迹答辩.pptx" screenshot --grid 4 -o /tmp/d.png  # 一张图看完 16 页
```
