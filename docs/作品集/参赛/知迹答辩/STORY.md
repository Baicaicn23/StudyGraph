# STORY.md · 知迹 答辩 PPT 叙事（v2 · 科普主线 + 专业锚点）

> v2 重写原因：v1 是"产品介绍体"（痛点→闭环→架构→功能→承诺→证据），技术含量被拆散在 6 页里，
> 评委记不住做了什么；且整页四层架构图对非技术听众是灾难。v2 改为**技术叙事 + 双层表达**。

## ① 意图

- **受众**：赛道十三评审，教育背景与技术背景混杂。**多数人不是做 Agent 的**。
- **目标**：让非技术听众听懂"为什么要管这些事、我们怎么管的"，同时让技术评委在**第 09 页**看到分量。
- **调性**：说人话 / 不堆术语 / 每页只留一个真东西。
- **边界**：不出现分层架构图、不出现八模块清单、不出现类名与代码；术语**首次出现必须配人话**。

## ② 表达规则（硬约束）

1. 每页 = **一句人话（标题）+ 一个场景/类比（主体）+ 一个专业锚点（底部条）**。
2. 锚点放**页脚上方的一条**，一页最多一个；主叙事区不出现术语。
3. 术语双写：`存档（检查点）`、`门禁两道（权限双层）`、`开会纪要（上下文压缩）`、`四条找法（四路召回）`。
4. 深度**递增**：02 纯科普 → 03–05 各留 30% → 06–07 各留 40% → 08 回到演示 → 09 最硬（60%）。
