# STORY.md · 知迹 答辩 PPT 叙事（v4 · kami 设计系统）

> v4 = 用 **tw93/kami**（MIT）的设计系统重做生成管线：纸感底 + 墨蓝衬线 + 细线表，
> 产出仍是**原生可编辑 pptx**（python-pptx）。内容沿用 v3 的 11 页与结论式标题。

## ① 为什么要换到 kami

| | v3（slidep / SlideDSL） | v4（kami） |
| --- | --- | --- |
| 视觉 | 蓝色学术版式，自己拼的网格 | 成型的设计系统：纸感底、墨蓝、衬线、细线表、留白节奏 |
| 产物 | 原生 pptx（可编辑） | 原生 pptx（可编辑），且表格/截图是同一套规范 |
| 改一页 | 改 `.slide` 源 → `upsert-dsl` → lint | 改 `kami_slides.py` 的 `main()` → 重跑 → 后处理 |
| 自查 | 逐页 VLM 视觉检查（会限流、会随机失败） | `officecli --grid` 一张总览图（本地、秒级） |

**v3 蓝版源文件仍在 `slides/`（已归档）**，需要回退时从 git 取旧 pptx。

## ② 表达规则（沿用 v3，仍然有效）

1. **标题 = 结论**，不用比喻当标题；只读标题连起来要能读完整条论证。
2. 每页只有**一个证据形态**（表 / 截图 / 数据卡 / 分栏），不混。
3. 数字必须带**口径**（样本量、测量方式）。
4. 术语只在必要处出现，且附一句中文解释。
5. 不设章节分隔页（Kami 规范明令），章节靠 eyebrow 标注。

## ④ 深度分配

术语与数字集中在 04 / 06 / 07 / 08；02 / 03 / 09 / 11 以场景、结论与数据为主。
**最深的一页是 10**（主动交代短板），这是可信度落点，不要删。

## ⑤ 生成与后处理

```bash
cd docs/作品集/参赛/知迹答辩
uv run --with python-pptx --with pillow python kami_slides.py --out 知迹答辩.pptx
uv run python scripts/ppt_postprocess.py --ppt 知迹答辩.pptx --render /tmp/deck-grid.png
```
- 内容唯一数据源：`kami_slides.py` 的 `main()`；页名在 `slide_titles.json`（两处都要改）。
- 交付件：11 页 / 168 KB / 页名 11 / 11 落盘 / `officecli validate` 无错。
