# STORY.md · 知迹 答辩 PPT 叙事（v3 · 项目汇报体）

> v3 重写原因：v2 过度科普（比喻多、技术栈藏起来、像产品介绍不像项目汇报），用户判定"太像玩具式汇报"。
> 本版依据调研结论重做：**金字塔原理 + 行动标题 + 一页一观点 + 技术选型表 + 数据口径 + 主动边界**。

## ① 调研依据（2026-10-21）

| 结论来源 | 采纳的规则 |
|---|---|
| 金字塔原理（Minto）/ SCQA | **结论先行**：第 2 页即给出三条结论，后面每页只证明其中一条 |
| 行动标题（Action Title） | 每页标题写**整句结论**（含数字），不写主题词；标题连读即完整论证 |
| 一页一观点 | 每页只主张一件事；标题出现"和"就拆页 |
| 咨询业版式惯例 | 固定母版 + 网格；图表下方必带"所以呢"；数字必带口径 |
| 项目 / 答辩结构惯例 | 封面 → 摘要 → 背景 → 选型 → 架构 → 实现 → 使用 → 指标 → 边界 → 致谢 |
| AI 做 PPT 的技术路线（模板注入 / Slides-as-Code / HTML→PPTX / SVG→DrawingML / 多智能体 + VLM 自检） | 沿用**代码化生成 + 逐页视觉检查**路线（`workbuddy-pptx` / SlideDSL），每页过布局与视觉检查 |

## ② 表达规则

1. **标题 = 结论**，不用比喻当标题；比喻最多出现在正文一行。
2. 每页必含：**结论标题 + 证据（图 / 表 / 截图）+ 口径说明**。
3. 数字必须带**口径**（样本量、测量方式、在哪测的）。
4. 术语可出现，但必须**附一句中文解释**（不设独立术语页）。
5. 母版统一：深蓝顶条 64px（左作品名 / 右章节名）、页脚（左全称 / 右页码）、内容区 x76–1204。
