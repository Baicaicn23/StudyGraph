# 01 · 作品说明

> 作品名（暂定）：**知迹 智能学习助手**。赛道：（十三）智慧教育与智能软件类。

## 一、作品是什么

知迹 是一个面向大学生的**个人学习助手**：平时把资料**分学科**沉淀进知识库、
聊天随手记笔记；期末从知识库与错题**自动出题**、安排复习。它不是"问一句答一句"
的聊天框，而是围绕一个真实痛点设计的系统——

> **作业散落在各个课程系统里，平时不整理，期末就没有题可复习。**
> 所以核心不是"更会聊天"，而是**让学科知识库成为平时的沉淀罐，期末从库里长出复习材料**。

技术上，它用 **LangGraph** 把"一次学习回合"做成一张**显式、可观测、可断点续跑、可人工介入**
的状态图，并用一套完整的 Agent 工程模块（工具、记忆、规划、护栏、评测、可观测）把它撑起来。

## 二、目标用户与场景

- **用户**：有期末考试压力的在校大学生（多学科并行）。
- **场景**：平时作业/讲义随手沉淀；期末按学科检索复习、做错题、自测。
- **关键承诺**：**AI 出题不会擅自改动你的数据**（写操作先经人工确认）。

## 三、系统架构

后端按**洋葱 / 六边形**分层（依赖只朝内），前端为 Next.js：

```text
frontend/  Next.js 聊天界面
      │  HTTP / SSE
interfaces/       FastAPI + SSE 接口层（组合根）          ← 依赖全部
application/      用例编排 + 端口(Protocol) + LangGraph 图  ← 依赖 domain
domain/           纯领域逻辑（排期/出题/检索/RRF/护栏…）    ← 仅标准库
infrastructure/   SQLite / Embedding / LLM / MCP / 文件解析 ← 实现端口
```

一次学习回合的图（LangGraph）：

```text
START → route → plan → agent ⇄ tools → END
       意图路由  规划   模型+工具循环
```

- **route**：判意图（讲解/练习/进度/检索/计算/闲聊），路由到子智能体。
- **plan**：复杂请求先规划再执行（plan-and-execute）；简单请求跳过。
- **agent ⇄ tools**：模型决定调工具、工具结果回填、继续推理，直到得到回答。
- **tools**：执行层权限拦截 + 人在环中断。

## 四、核心功能

| 功能 | 说明 |
| --- | --- |
| 学科知识库 + 混合检索 | 上传/沉淀资料；检索走 **FTS5 trigram 中文分词 + 向量余弦 + 同义词扩写 + 两字词 LIKE** 四路召回，**RRF 加权融合**，结果带出处 |
| 多格式资料入库 | PDF / Word / PPT / Excel **原样秒传 + 懒解析**（用时才建索引）；PDF 与 PPT 按页切块、**引用能落到具体页** |
| 图片板书入库 | 拍照的板书 / 课件截图由多模态模型**转写成 Markdown** 后入库，可被检索 |
| 笔记阅读与问答 | 三栏阅读页（目录树 / 正文 / AI 助手 + 大纲滚动联动）；**划词提问** |
| 聊天即问 | 上传资料后提问，回答基于检索片段并给出处；检索范围可交给模型判断或手动锁定 |
| HITL 沉淀 | "记住/存一下"时**先弹确认再落库**，人在环 |
| 学习闭环 | 记错题（带学科 + **错误类型**）→ 出**变式题**（模型写题、失败回退模板，难度按掌握度自动分档）→ 作答后可看**参考答案与关键步骤**（按需生成）→ 自评 → **间隔重复排期 + 掌握度** |
| 长期记忆 | 从对话抽取"你是谁、在学什么"并注入提示词（标注为背景，非指令），**按课程隔离** |
| 今日复习 | 汇总到期题 / 薄弱学科 / 近期误区，给出"今天做什么"；含**学习周报**与活跃度热力图 |
| 日程 | 想法先进**收件箱**，再一键排进时间轴（确定性算法，可预期）；与学习闭环**刻意不联动** |

## 五、技术亮点（Agent 工程模块）

- **显式状态图 + 检查点**：LangGraph 图 + `AsyncSqliteSaver`，会话可断点续跑（也是 HITL 的前提）。
- **工具最小权限（双层）**：schema 层只给模型看允许的工具，执行层再拦黑名单——进度 agent 全禁、练习 agent 只读、讲解/检索/闲聊可读写。
- **护栏**：输入拦越界与提示词注入；输出拦空回答与系统提示词泄漏。
- **工具可靠性**：单次超时 + 只对可重试错误做有限退避重试；失败转成工具消息，不炸整回合。
- **上下文工程**：历史过长时压缩较早轮次（只从整轮边界裁剪，不拆散工具调用对）。
- **规划 + 模型路由 + 成本控制**：复杂请求规划；按意图/复杂度选模型档位；token 记账 + 当日预算超限阻止。
- **MCP 客户端**：自写 stdio JSON-RPC，启动外部 server、发现并注册外部工具。
- **评测与可观测**：检索 Hit@K/MRR 与意图准确率基线门禁 + 回合 trace 五层归因。

## 六、创新点

1. **面向"学习"而非"问答"**：把知识库、错题、练习、掌握度、目标串成闭环，而不是单轮问答。
2. **用状态机做 Agent**：回合流程显式可画、可断点、可人工介入，而不是藏在黑盒里。
3. **最小权限 + 人在环**：写操作在执行层被强制"人工确认"，是产品承诺而非提示词劝告。
4. **可评测**：检索/意图有固定考卷与基线门禁，改动可量化——"把模型做成可度量的系统"。

## 七、展示形式

- 后端：FastAPI + SSE（`zhiji.interfaces.api:app`）。
- 命令行：`zhiji`（聊天）、`zhiji-demo`（播种演示数据）、`zhiji-eval`（评测）、`zhiji-trace`（诊断）。
- 前端：Next.js **7 个页面**（AI 对话 / 知识库列表 / 笔记阅读 / 错题练习 / 今日复习 / 日程）。

## 八、当前边界（诚实说明）

- 单用户（多用户登录与数据隔离未做）。
- 仍不支持的：**在线监控聚合面板**、反思式自我批判（evaluator-optimizer）、Reranker 重排。
- 这些在 [02-主张与证据核对表](02-主张与证据核对表.md) 中标注为「计划中」，**不以已完成口径出现**。
- 已从本节移出（现已实现，见 02）：多模态发图（视觉转写）、出题难度分层。
