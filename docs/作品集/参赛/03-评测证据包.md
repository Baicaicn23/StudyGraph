## 二、检索评测

```bash
uv run studygraph-eval retrieval \
  --dataset evals/datasets/retrieval.json \
  --baseline evals/baselines/retrieval.json
```

实际输出：

```text
== retrieval 评测 ==
  cases: 6
  k: 3
  hit_at_k: 1.0
  mrr: 1.0
  ✓ 无回归
```

- **数据**：5 篇自编讲义 + 6 个问题，每题标注正确片段（gold）。
- **流程**：真实检索管线（FTS5 trigram + 向量 + RRF）→ 命中即算分。
- **指标**：Hit@3（正确片段是否在前 3）、MRR（首个正确项的倒数排名均值）。
- **可复现性**：评测**强制使用确定性 Mock 向量**，同一版本任何人跑出同样的分数。
- **回归门禁**：指标掉超过容差（0.05）时命令**退出码为 1**，可直接进 CI 拦截回归。

> 诚实说明：这是**自建的小考卷**，用于回归门禁而非衡量绝对能力；它证明的是
> "改动不会让检索悄悄变差"，不是"检索比别家强"。

## 四、回合诊断（trace）

```bash
uv run studygraph-trace --thread <thread_id>
```

真实输出（一个"知识库为空"的检索回合）：

```text
回合 thread=tr1
├─ 用户消息： 我的笔记里怎么讲导数的？
├─ 意图：retrieval  →  retriever
├─ 工具：knowledge_search  [空]
└─ 归因：retrieval
   ⚠ 检索返回空结果：模型没有资料可用
```

它把一次会话读成诊断树，并**归因到责任层**（检索 / 工具 / 模型 / ok）——
"失败了"之外，还能指出该改哪一层。

## 八、真实模型端到端验证（2026-10-09，DeepSeek-V4.1-Flash）

模型：`deepseek-flash`（DeepSeek-V4.1-Flash GA 版），OpenAI 兼容接口接入，
`STUDYGRAPH_MAX_OUTPUT_TOKENS=4096`。以下为 SSE 流式对话的**节选实录**
（演示数据：5 学科库 / 15 笔记 / 4 条误区，user_id=local）。

### 场景 1：苏格拉底式讲解 + 个人数据优先 + 错题联动

问：「讲一下定积分和不定积分的区别」

> 我先看看你自己的笔记里有没有沉淀过这块内容……先说一句好消息：**这块你的
> 笔记里已经沉淀过了。** 📍出处：《高等数学-微积分 / 定积分与不定积分的区别》……
> ⚠️ 但还有一件事得提你一下——你的**错题本里已经有一条**记录：题目：定积分和
> 不定积分有什么区别？｜当时记下的误区："我把结果类型搞混了……"
> 所以这次我们换个方式：**不直接背结论**，先看你到底是"没记住"还是"记混了"。
> 你试着自己回答下面三步…… 1. 先不看笔记，你觉得它们各自的结果长什么样？……
> 先说说第 1 步吧，答对我就往下推一层……哪一步卡住了直接说，我换个提示。

→ 一条回答里同时命中三条红线：**检索自己的笔记并标出处、引用错题记录做归因、
拆成递进小问题引导而非直接给答案**。

### 场景 2：错题归因（模式识别）

问：「帮我分析一下我的错题，我最近老在哪些地方出错？」

> ……你的错题一共 4 条，分布是：**微积分 2 条、线代 1 条、数据结构 1 条**……
> **模式一：概念边界模糊（4 条里占 3 条）**……共同点是**把「一般情况下成立」
> 当成了「永远成立」**……**模式二：靠死记硬背（1 条）**——这条我怀疑是模式一的
> *结果*：概念没吃透，公式就只能硬背……那我们从模式一里最容易拿分的那条开始。

→ `mistake_search` 返回频次分布后，模型做了**跨条目的模式归纳与归因**，
而不是逐条复述——这是"私教"与"答题器"的区别。

### 场景 3：检索出处 + 库过滤 + 指出知识盲区

问：「我的笔记里怎么讲特征值的？」（选中：线性代数）

> 我在你的**线性代数**库里找到了关于特征值的笔记……📚 出处：线性代数 / 《特征值
> 与特征向量》……你笔记里的版本回答了「是什么」和「长什么样」，但**没写「怎么算」**
> ——特征方程 det(A−λI)=0 那套解法，你的资料里还没沉淀。这块我先不替你铺开……

→ 库过滤只返回选中库；模型主动指出**笔记里缺什么**（"这部分你还没沉淀"），
并建议补齐——红线 1 的完整形态。

### 场景 4：写入需确认（HITL）与成本

- 「记住：拉格朗日中值定理的条件是……」→ 正常触发**确认中断**，批准后才落库；
  拒绝则不写入（写权限永远在学生手里）。
- 成本记账（`/api/usage`）：上述 4 个场景 + 冒烟共 11 次调用，**20,624 tokens**
  （输入 15,722 + 输出 4,902）。按 DeepSeek 2026-09 牌价（峰值输入 $0.30/M、
  输出 $1.20/M）折算 **约 $0.01**；错峰约减半。每次调用的 token 均逐笔入账。
