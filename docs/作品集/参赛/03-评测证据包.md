## 二、检索评测

```bash
uv run studygraph-eval retrieval \
  --dataset evals/datasets/retrieval.json \
  --baseline evals/baselines/retrieval.json
```

实际输出：

```text
== retrieval 评测 ==
  cases: 6
  k: 3
  hit_at_k: 1.0
  mrr: 1.0
  ✓ 无回归
```

- **数据**：5 篇自编讲义 + 6 个问题，每题标注正确片段（gold）。
- **流程**：真实检索管线（FTS5 trigram + 向量 + RRF）→ 命中即算分。
- **指标**：Hit@3（正确片段是否在前 3）、MRR（首个正确项的倒数排名均值）。
- **可复现性**：评测**强制使用确定性 Mock 向量**，同一版本任何人跑出同样的分数。
- **回归门禁**：指标掉超过容差（0.05）时命令**退出码为 1**，可直接进 CI 拦截回归。

> 诚实说明：这是**自建的小考卷**，用于回归门禁而非衡量绝对能力；它证明的是
> "改动不会让检索悄悄变差"，不是"检索比别家强"。

## 三、意图分类评测

```bash
uv run studygraph-eval intent \
  --dataset evals/datasets/intent.json \
  --baseline evals/baselines/intent.json
```

实际输出：

```text
== intent 评测 ==
  cases: 15
  accuracy: 1.0
  ✓ 无回归
```

15 句标注样本覆盖六类意图；规则分类器准确率 1.000。错分明细会随结果一并输出，
便于定位。

## 四、回合诊断（trace）

```bash
uv run studygraph-trace --thread <thread_id>
```

真实输出（一个"知识库为空"的检索回合）：

```text
回合 thread=tr1
├─ 用户消息： 我的笔记里怎么讲导数的？
├─ 意图：retrieval  →  retriever
├─ 工具：knowledge_search  [空]
└─ 归因：retrieval
   ⚠ 检索返回空结果：模型没有资料可用
```

它把一次会话读成诊断树，并**归因到责任层**（检索 / 工具 / 模型 / ok）——
"失败了"之外，还能指出该改哪一层。

## 五、成本记账

```bash
curl http://127.0.0.1:8011/api/usage
```

```json
{"total_tokens":357,"by_model":[{"model":"study-mock","input_tokens":301,"output_tokens":56,"total_tokens":357,"calls":3}]}
```

每次模型调用的 token 都会被记录；可设当日预算，超限即阻止真实调用。

## 六、复现清单（给评委的一页）

```bash
# 0. 安装
uv sync

# 1. 播种演示数据（5 学科 / 15 笔记 / 3 误区）
uv run studygraph-demo --reset

# 2. 全自动测试（104 passed，全 Mock 零消耗）
uv run pytest -q

# 3. 评测门禁
uv run studygraph-eval retrieval --dataset evals/datasets/retrieval.json \
  --baseline evals/baselines/retrieval.json
uv run studygraph-eval intent --dataset evals/datasets/intent.json \
  --baseline evals/baselines/intent.json

# 4. 起服务（前端 http://localhost:3000，后端 http://127.0.0.1:8011）
./scripts/dev.sh
```

## 七、诚实说明

- 图文数据（检索/意图考卷）为**作者自行标注**，规模小，定位是**回归门禁**。
- 所有数字来自确定性 Mock，**不依赖真实模型、不消耗额度**；真实模型下的质量
  不在本证据包内（属于后续工作）。
