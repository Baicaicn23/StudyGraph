# 知迹 作品介绍文档

**作品名称**：知迹 —— 会整理、会出题的学习 Agent
**参赛赛道**：赛道十三 · 智慧教育与智能软件类
**技术栈**：LangGraph · FastAPI · SQLite · Next.js 16

---

## 一、项目定位

### 1.1 创作背景

大学生的学习资料与练习需求分散在多个课程平台与聊天工具中：讲义在网盘、作业在平台、错题在本子上。平时没有整理的动力，等到期末想复习时，"题"和"资料"都已经找不回来了。

与此同时，大模型应用普遍存在"黑盒"问题：用户无法判断答案依据何在，也无法确认系统是否会擅自改动自己的数据。

现有工具大多只解决"问答"这一环——资料被存下、答案被说过、错题被标过，都没变成下次还能用的东西。缺的不是更聪明的问答机器人，而是一个能把日常碎片自动攒成复习材料的沉淀系统。

### 1.2 目标用户

多学科并行、有阶段性考核压力的在校大学生（个人自用场景；无鉴权与多用户隔离）。

### 1.3 拟解决的问题

| 问题 | 现状 | 知迹的做法 |
| --- | --- | --- |
| 资料散落、平时不整理 | 网盘囤了上百页提纲，没索引等于没存 | 传进来即按学科归档，秒传落盘、用时解析，可被检索 |
| 题目与讲义对不上 | 网上找题，定义与教材不一致 | 只从**你自己的资料**出题，切到页给出处 |
| 做错了没人管 | 同类型再考，照错不误 | 记错因 → 生成变式题 → 间隔重复排期 |
| AI 是黑盒 | 不知道它查了什么、会不会乱改 | 回合画成显式状态图；写操作强制人工确认 |

### 1.4 应用场景

1. **整理资料**：上课把讲义、课件、笔记传进来 → 按学科分好，PDF 可翻到第几页。
2. **自动出题**：考前让它按自己的资料出题 → 难度按掌握度自动分档。
3. **闭环复习**：每天打开"今日复习"做几道 → 做错的记下错因 → 下次出题会照顾到。

### 1.5 最终形成的成果

一个可本地运行的 Web 应用（后端 + 前端 + 单文件数据库），以及一条 **4 分 32 秒的作品评审视频** 与 **18 页作品汇报 PPT**。全项目 **284 项自动化测试**全部离线通过，检索与意图各有一份固定考卷作为回归门禁。

## 二、主要创新

### 创新一：把"知识库"从资料夹重新定位为"复习原料库"

多数工具的知识库是**检索用的资料夹**——存下来，等提问时搜一次。知迹的知识库是**期末复习的原料库**——日常沉淀的碎片在这里长出模拟考。

这个定位差异带来三个具体设计：只从用户自己的资料出题（不做通用题库）、每道题可回溯到具体页码（"来自这份资料"太笼统，"切到页"才知道考的是哪一段）、以及资料与出题共享同一份底账（不需要两套数据同步）。

### 创新二：用显式状态机做 Agent，而非提示词堆叠

一次学习回合被建模为一张**可观测、可断点、可人工介入**的状态图：

```
START → route → plan → agent ⇄ tools → END
       意图路由  规划   模型+工具循环
```

与"把整段对话丢给模型"的做法相比，这张图带来三件事：意图判断是**规则**而非猜测（六类意图，15 句标注样本准确率 1.0）；工具调用是**受控循环**（最多 6 轮）而非自由发挥；每一步都**可归因**（一次会话能读成诊断树，指出该改检索、工具还是模型层）。

### 创新三：最小权限 + 人在环，写操作在执行层被强制

"AI 不改你的数据"如果只写在提示词里，是一句请求；知迹把它做成了四道闸门：

1. **模型提议** —— agent 想调某个工具；
2. **schema 白名单** —— 禁用的工具根本不出现在提示词里；
3. **执行层判定** —— `is_tool_allowed` 逐次查询，硬发也拦得住；
4. **人在环** —— 写操作 `interrupt()` 等确认，取消则一个字节都不动。

任何一道闸门拦下，这一回合就地停住。这是**代码里的强制**，不是**文案里的承诺**。

### 创新四：可评测——把"改完变好了还是变差了"变成可判定的问题

检索与意图各有固定考卷与基线 JSON，指标掉出容差时命令**退出码为 1**，可直接进 CI 拦截回归。词面精排还有**消融开关**——关掉后 MRR 从 0.9714 降到 0.9571，机制有没有用当场可见。

### 创新效果（实测数据）

| 指标 | 数值 | 复现命令 |
| --- | --- | --- |
| 检索 Hit@3 = MRR | **0.9714**（35 题 / 21 篇语料） | `zhiji-eval retrieval …` |
| 检索 · 接真实向量 | **35 / 35 全中** | `… --embedding real` |
| 检索 · 消融（关精排） | MRR **0.9714 → 0.9571** | `… --no-rerank` |
| 意图分类准确率 | **1.0**（15 句 / 六类意图） | `zhiji-eval intent …` |
| 自动化测试 | **284 passed**（全 Mock，零 API 消耗） | `uv run pytest -q` |

## 三、技术与创作实现

### 3.1 技术路线

```
frontend/  Next.js 16 聊天与学习界面
      │  HTTP / SSE
interfaces/       FastAPI + SSE 接口层（组合根）      ← 依赖全部
application/      用例编排 + 端口(Protocol) + LangGraph 图  ← 依赖 domain
domain/           纯领域逻辑（排期/出题/检索/RRF/护栏…）    ← 仅标准库
infrastructure/   SQLite / Embedding / LLM / MCP / 文件解析 ← 实现端口
```

**依赖只朝内**：应用层只依赖 `application/ports.py` 里的 Protocol，不 import 任何具体实现——换数据库、换模型、换检索都不用改业务代码。领域层是纯逻辑，测它不用起数据库、不联网。

### 3.2 关键实现

**四路混合检索**：中文资料没有单一找法，四路并行召回后加权 RRF 融合（k=60），再做词面精排。

| 通道 | 权重 | 解决什么 |
| --- | --- | --- |
| 原查询 FTS5 trigram | 1.0 | 字面精确匹配 |
| 同义 / 中英扩写 FTS | 0.5 | 换个说法也能找到（推断出来的，权重该低于字面命中） |
| 两字词 LIKE | 0.8 | 短词专门兜底 |
| 向量语义 | 1.0 | 零字面重叠也能召回 |

精排只调顺序、不增删候选（可关做消融对照）。**加能力请加通道，别改查询词生成**——后者会动评测基线。

**资料双轨入库**：二进制文件先**原样秒传**落盘不解析，用到时才建索引；PDF 与 PPT 逐页切块并保留页码出处，因此每道题都能跳回原页。损坏文件按魔数校验挡在门外。

**学习闭环建模**：错题按**错误类型**（概念混淆 / 步骤遗漏 / 条件误读 / 计算失误 / 表述不清）归档 → 一条错因只出一道变式题（不重复刷）→ 作答后按需生成参考答案与关键步骤（懒生成并缓存，首次 3.7s、之后 0.02s）→ 四档自评映射掌握度增减与下次间隔（again 立即 / hard 1 天 / good 3 天 / easy 7 天）。

**工程保障**：工具双层权限、HITL 写入确认、输入输出护栏、工具超时与有限退避重试、上下文压缩（抽取式摘要，从整轮边界裁剪不拆散工具调用对）、规划与模型路由、token 记账与日预算闸门、MCP 客户端（自写最小 stdio JSON-RPC）、回合 trace 五层归因。

### 3.3 系统结构与交互

**前端**：Next.js 16（App Router + Tailwind + Radix Primitives），7 个路由 —— AI 对话 / 知识库 / 笔记阅读 / 错题练习 / 今日复习 / 日程 / 错题本旧路径重定向；侧栏功能导航 5 项。三栏阅读页支持目录树、正文、AI 助手与大纲滚动联动，支持划词提问。

**后端**：FastAPI + SSE 流式接口，全部端点在一个组合根；CLI 提供 `zhiji`（聊天）、`zhiji-demo`（播种演示数据）、`zhiji-eval`（评测）、`zhiji-trace`（诊断）四个入口。

**数据**：全部业务数据存于单个 SQLite 文件，可随文件整体迁移，无需独立数据库服务。

## 四、成果状态

严格区分已完成与未完成，以下均为**实测可运行、可复现**的状态。

### 4.1 已完成

- **知识库**：多格式资料上传归档、四路混合检索、页码级出处、智能选库与回落全库、三栏阅读与划词提问、图片视觉转写入库。
- **学习闭环**：错题记错因、变式题派生、难度三档分档、答案详解懒生成与缓存、四档自评、掌握度增减、间隔重复排期、今日复习规划、学习周报、活跃度热力图。
- **对话**：六类意图路由、显式状态图、私教人格与掌握度自适应讲解、SSE 过程流推送、课程空间隔离、长期记忆（按课程隔离）。
- **工程**：工具双层权限、MCP 桥、HITL 写入确认、输入输出护栏、超时与退避重试、上下文压缩、规划与模型路由、成本记账与日预算、回合 trace、断点持久化与检查点级联清理。
- **日程**：收件箱 + 时间轴 + 迷你日历，**排期是确定性算法，零模型调用**。
- **质量**：284 项自动化测试；检索 35 题与意图 15 句两份考卷及基线门禁；消融对照开关。

### 4.2 正在完善

- 长期记忆的生命周期（过期 / 替换 / 删除三种状态尚未实现）——已如实写入项目体检报告。
- 任务级成功率评测（现有评测覆盖检索与意图，尚未覆盖端到端任务完成率）。

### 4.3 明确未做（不以已完成口径出现）

在线监控聚合面板、Reranker 重排、反思式自我批判（evaluator-optimizer）、多用户登录与数据隔离。

**主动选型说明**：鉴权与多租户被**主动放弃**——单机单用户演示场景下，多一条功能就多一条出错路径。工程精力全部压在工具权限、写入确认与评测门禁上，因为这三项直接决定"敢不敢让 AI 动手"。

### 5.3 原创贡献说明

本作品的核心创意与技术方案均由成员A 提出并实现：把"知识库"从检索用的资料夹重新定位为"期末复习的原料库"（决定了只从用户自己的资料出题、切到页给出处、资料与出题共享同一份底账这三条设计）；把一次学习回合做成显式状态图而非提示词堆叠（决定了意图判断用规则、工具调用受控、每步可归因）；把"AI 不改你的数据"做成执行层四道闸门而非文案里的承诺。成员B 负责将这套后端能力完整落地为可用的学习界面——包括三栏阅读、划词提问、四档自评与掌握度反馈这些把技术能力转化为学习体验的关键交互。

### 5.4 AI 工具与学生工作的边界

本项目在开发与文档环节使用了 AI 编程助手作为辅助工具，**所有 AI 产出均经逐条审阅、修改并通过测试后采用**；所有评测数字由学生亲自运行命令得出；每条技术主张在《主张与证据核对表》中有对应代码证据并标注完成状态。详细的工具清单、使用环节、人工处理过程与原创贡献说明见《AI 工具使用补充说明》。

**明确一点**：AI 工具在本项目中是**编码与写作的辅助工具**，不是作品的技术组成部分。作品本身的技术实现（状态图编排、四路检索、权限闸门、评测门禁）由学生设计并实现。

### 5.5 应用场景、测试结果与用户反馈

- **应用场景**：多学科并行、有阶段性考核压力的在校大学生，个人自用场景。典型流程为"传讲义 → 按资料出题 → 每日复习 → 记错因 → 下次加重"。
- **测试结果**：284 项自动测试全部离线通过；检索 35 题考卷 Hit@3 = MRR = 0.9714（接真实向量 35/35 全中），消融对照 MRR 0.9714 → 0.9571；意图分类 15 句准确率 1.0；真实模型端到端四个场景实录见《AI 工具使用补充说明》。
- **用户反馈**：本次参赛为单机演示阶段，尚未开展规模化用户测试，故未提供用户反馈数据。

## 六、应用价值

1. **让"平时积累"真的能兑现**：把知识库从"搜索用的资料夹"重新定位为"期末复习的原料库"，使日常碎片自然沉淀为可出题的材料，把"期末临时找题"变为"平时自然沉淀"。
2. **让 AI 的执行过程可被信任**：显式状态图 + 四道权限闸门 + 写入前强制确认，使用户能判断答案依据何在，也能确认系统不会擅自改动自己的数据。
3. **让系统能力可被度量**：固定考卷 + 基线门禁 + 消融对照，使"改完变好了还是变差了"成为可判定问题，而非主观感受。
4. **对智慧教育的意义**：把 Agent 工程能力做成可评测、可解释的软件，而非一个演示用的壳——让每一位学生都可能拥有一个可持续积累、过程可信赖的学习助手。
