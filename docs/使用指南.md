# 使用指南

> 从零把 StudyGraph 跑起来，十分钟走完"算题 → 沉淀笔记 → 检索资料"的闭环。
> 想理解内部原理，读 [架构设计](架构设计.md)。

## 一、前置条件

- **Python 3.12+**
- **[uv](https://docs.astral.sh/uv/)**（依赖与虚拟环境管理）
- 可选：一个 OpenAI 兼容平台的 API Key（用真实模型时才需要；默认 Mock 不需要）

## 二、安装

```bash
uv sync
```

这一步会创建 `.venv` 并安装 LangGraph 等依赖。默认**不装** `langchain-openai`——
只有接真实模型时才需要它。

## 三、第一次运行（Mock，零成本）

```bash
uv run studygraph "帮我算一下 7 * 9"
```

预期输出：

```text
（模拟模型）根据工具返回的结果：63
```

这句话背后发生的事：意图被识别为"计算" → 路由到计算子智能体 → 模型请求调用
计算器工具（参数 `7 * 9`）→ 工具返回 `63` → 模型据此给出回答。**全程不联网、
不花额度。**

## 四、走一遍学习闭环

```bash
# 1. 沉淀一条笔记（写操作会先请求确认）
uv run studygraph "记住：我在准备月底的微积分测验"

#    如果不想交互确认，用 --yes 自动同意
uv run studygraph "记住：我在准备月底的微积分测验" --yes

# 2. 检索刚沉淀的内容
uv run studygraph "我的笔记里怎么讲微积分测验的？"
```

第 1 条命令会先打印：

```text
[需要确认] 保存到「日常沉淀」：《记住：我在准备月底的微积分测验》
  预览：记住：我在准备月底的微积分测验
  确认保存？(y/N)
```

输入 `y` 才落库——这就是 Human-in-the-Loop。

### AI 私教怎么聊（教学人格）

StudyGraph 的回答遵循「私教」总纲（三条红线）：**个人数据优先**（你的笔记 /
错题本里有的先检索再答，并标注出处）、**引导优先于告知**（先给思路提示和分步
小问题，不直接甩答案）、**贴合掌握水平**（按你各学科的掌握度调整讲解深度）。

值得在聊天里试的话：

```bash
# 苏格拉底式讲解：不给完整答案，一步步引导你推导
uv run studygraph "讲一下定积分和不定积分的区别"

# 错题归因：检索你的误区记录，统计同类错误频次（需要先记过错题）
uv run studygraph "帮我分析一下我的错题，我哪里错了"

# 贴合掌握水平：薄弱学科多用类比讲基础，强势学科讲本质讲拓展
uv run studygraph "我的线性代数学得怎么样？接下来怎么复习？"
```

## 五、启动 Web 界面（推荐）

界面里：左侧导航（**聊天 · 知识库 · 练习复习 · 错题本 · 今日复习**），聊天回答流式打字，
当助手要保存笔记时会弹出**确认框**（Human-in-the-Loop）。

```bash
# 首次：安装前端依赖
cd frontend && npm install && cd ..

# 一键起后端（8011）+ 前端（3000）
./scripts/dev.sh
```

打开 <http://localhost:3000>。前端默认连 `http://127.0.0.1:8011`，可用环境变量覆盖：

```bash
NEXT_PUBLIC_API_BASE=http://127.0.0.1:8011
```

在界面里试这几句，体验三种不同能力：

```text
帮我算一下 7 * 9               → 调计算器工具，回答里带 63
我的笔记里怎么讲微积分测验的？ → 检索你的资料并给出处
记住：我在准备月底的微积分测验 → 弹出确认框，确认后落库
```

## 六、命令行参数

| 参数 | 作用 |
| --- | --- |
| `message`（位置参数） | 本轮要说的话 |
| `--thread <id>` | 会话 id。相同 id 会**接着上一次**继续（断点持久化），默认 `local` |
| `--user <id>` | 用户标识（默认 `local`） |
| `--yes` | 自动同意所有需要确认的操作（HITL） |

继续一段旧对话：

```bash
uv run studygraph "接着上一题，再解释一下" --thread math
```

## 七、接入真实模型

任何 OpenAI 兼容平台都可以。推荐把配置写进项目根目录的 `.env`（Git 忽略，
程序启动时**自动加载**，无需手动 source）：

```bash
uv sync --extra openai

# .env 内容（DeepSeek-V4.1-Flash 示例，API 模型名 deepseek-flash）：
# STUDYGRAPH_LLM_PROVIDER=openai
# STUDYGRAPH_MODEL=deepseek-flash
# STUDYGRAPH_OPENAI_BASE_URL=https://api.deepseek.com/v1
# STUDYGRAPH_OPENAI_API_KEY=你的密钥
# STUDYGRAPH_MAX_OUTPUT_TOKENS=4096

uv run studygraph "讲解一下导数的几何意义"
```

也可以用环境变量临时覆盖（优先级高于 `.env`）。完整变量清单见
[`.env.example`](../.env.example)。注意：推理型模型务必设
`STUDYGRAPH_MAX_OUTPUT_TOKENS=4096`，避免输出被"思考"吃光导致空回答。

> 2026-07 起 DeepSeek 的 `deepseek-chat` / `deepseek-reasoner` 型号已退役，
> 统一使用 `deepseek-flash`（V4.1-Flash）或 `deepseek-v4-pro`。

## 八、数据存在哪里

| 路径 | 内容 |
| --- | --- |
| `data/studygraph.db` | 知识库（文档/片段）与 LangGraph 检查点（会话历史） |
| `data/knowledge/` | 预留的知识库原文目录 |

两个路径都可用环境变量覆盖：

```bash
STUDYGRAPH_DATABASE_PATH=/tmp/study.db uv run studygraph "计算 1 + 1"
```

清空数据：直接删掉 `data/studygraph.db` 即可（会同时清掉会话与知识库）。

## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 回答为空 / 只有一行空白 | 推理型模型把输出预算花在"思考"上 | 设 `STUDYGRAPH_MAX_OUTPUT_TOKENS=4096`（或更大） |
| 命令一直停在"确认保存？" | 这是 HITL，在等你输入 | 输入 `y` 或 `n`；非交互场景加 `--yes` |
| 检索"没有找到相关片段" | 该知识库为空，或查询词完全不在资料里 | 先沉淀/上传一些资料；换个更贴近资料的说法 |
| `ModuleNotFoundError: langchain_openai` | 没装可选依赖 | `uv sync --extra openai` |
| 想完全不联网跑 | 默认就是 Mock | 不要设 `STUDYGRAPH_LLM_PROVIDER=openai` 即可 |
| `database is locked` | 同一数据库被多个进程同时写 | 串行运行命令；或换一个 `STUDYGRAPH_DATABASE_PATH` |

## 十、运行测试与检查

```bash
uv run pytest -q --basetemp=/tmp/sg-pytest   # 117 passed（本机沙箱须指定 basetemp）
uv run ruff check src tests
```

评测与诊断（都零 API 消耗）：

```bash
# 评测门禁：有基线时掉超过容差 → 退出码 1
uv run studygraph-eval retrieval --dataset evals/datasets/retrieval.json \
  --baseline evals/baselines/retrieval.json
uv run studygraph-eval intent --dataset evals/datasets/intent.json \
  --baseline evals/baselines/intent.json

# 回合诊断：把一次会话读成诊断树
uv run studygraph-trace --thread <thread_id>
```

测试全部跑在确定性 Mock 上，**不消耗任何 API 额度**。

## 十一、用接口上传资料 / 走复习闭环

界面之外，也可以直接调接口（复习/错题界面正在完善中）：

```bash
# 上传一份资料（TXT / Markdown / PDF）
curl -F "library=高等数学" -F "file=@导数笔记.md" \
  http://127.0.0.1:8011/api/knowledge/upload

# 记录一条误区
curl -X POST http://127.0.0.1:8011/api/feedback -H 'Content-Type: application/json' \
  -d '{"library":"线性代数","question":"什么是特征值？","note":"我把特征向量搞混了"}'

# 从错题出题（Mock 下出模板题；接真实模型则由模型写题）
curl -X POST http://127.0.0.1:8011/api/practice/generate -H 'Content-Type: application/json' \
  -d '{"source":"mistakes","count":3}'

# 到期题
curl http://127.0.0.1:8011/api/practice/due

# 作答自评：again / hard / good / easy（间隔重复 + 掌握度）
curl -X POST http://127.0.0.1:8011/api/practice/answer -H 'Content-Type: application/json' \
  -d '{"question_id":1,"rating":"good"}'

# 今日复习建议
curl http://127.0.0.1:8011/api/study/plan
```
